Five deployments of the same version, each stopping at a different gate:

  scenario                      stopped at   live after   traffic   who saw it
  clean release                 promoted     v1.1.0       100%      everyone
  tests failed                  preflight    v1.0.0         0%      nobody
  irreversible migration        preflight    v1.0.0         0%      nobody
  starts but cannot serve       health       v1.0.0         0%      nobody
  canary over error budget      canary       v1.0.0         0%      10% of users

Read the last column downwards. It is the whole argument for having several
gates rather than one good one: the same defect costs a different amount
depending on where it is caught, and the difference is users.

Note the health case in particular. The process STARTED -- liveness was fine.
Readiness was not, so it could not serve. A deployment system that only checks
liveness reports that release as healthy and leaves it serving errors.
