Measured on macOS 26.5.1 (Apple Silicon), Python 3.14.0, pytest 9.1.1.

  python3 examples/stream_ux_demo.py -> 20 lines, exit 0
  bash tests/run_tests.sh            -> 16 passed in 0.02s

Time is a LOGICAL clock -- one tick per observable moment -- so these numbers
are exact rather than "about right" on a busy laptop. A wall-clock version of
this lab would produce a different answer every run and could not be asserted
on.

The five runs, all delivering the same 47-character answer:

  run                                 ending     total  ttft  chars  felt
  streaming, healthy                  done        12     4     47     4
  blocking (no partial output)        done        20    12     47    12
  stream fails midway, partial kept   error        8     4     21     4
  stream fails midway, discarded      error        8     4      0     4
  cancelled by user                   cancelled    7     4     18     4

Two comparisons carry the lesson.

Rows 1 and 2 deliver identical content and the perceived wait is 4 against 12.
Streaming is not less work; it is an earlier first moment.

Rows 3 and 4 fail at the same instant, in the same number of ticks. The only
difference is that one of them also threw away 21 characters the user had
already read.
