# What may legitimately differ on another machine

Everything in this directory was captured from a real run against the
shipped `data/exp_a.csv` and `data/exp_b.csv`, which are themselves generated
once, deterministically, by `examples/generate_data.py` with fixed seeds
(`dataset.SEED_A = 119001`, `dataset.SEED_B = 119002`, arrival-order shuffle
seeds 2 and `SEED_B + 1`). Because the CSVs are checked in rather than
regenerated per run, every number below is **exact and reproducible** on any
machine with the same two files -- these are not simulation results that
drift with the platform's random number generator internals.

What can still differ:

- `run_tests.txt`'s platform line (`platform macOS-...`) and the `exe` line
  reflect the machine and Python build this was captured on. The version
  numbers for `numpy` and `pytest` will differ if the lab's `.venv` is
  rebuilt against a newer release than 2.5.2 / 9.1.1 -- the harness checks
  numpy's version against `requirements/requirements.txt`, not against the
  literal numbers printed here.
- Wall-clock timings printed by pytest (e.g. `12 passed in 0.17s`) will vary
  run to run and machine to machine; nothing in the harness asserts on them.
- If `data/exp_a.csv` or `data/exp_b.csv` is regenerated by re-running
  `examples/generate_data.py`, the output is byte-identical to what is
  checked in, because generation is fully seeded. Regenerating is never
  required to run this lab.

Everything else -- every p-value, every confidence interval, every segment's
lift, every checkpoint in the peeking walk, every verdict -- is exact
arithmetic over the fixed, checked-in data and will reproduce identically
on any machine with a correct implementation.
