# Week 22 project — House Price Model

This week was **Regression**: a single continuous target instead of a class
label, a loss that is a *choice* rather than a given, multicollinearity and
what it does to coefficients versus predictions, ridge and lasso as two
different answers to the same overfitting problem, the metrics that describe
a continuous prediction and the ways they can mislead, building OLS from
scratch to see where the normal equations lose precision, and a full
synthesis run with residual diagnostics on Day 154.

**A dataset honesty note, read this before anything else.** The curriculum
calls this project "House Price Model," and this course runs fully offline
(no lab or project may reach the network), which rules out
`sklearn.datasets.fetch_california_housing` — it downloads on first call.
The classic `sklearn.datasets.load_boston` is not an option either: it was
removed from scikit-learn years ago because of a documented ethical problem
with one of its features, and no version of this course will tell you to
downgrade scikit-learn to get it back. The only regression dataset bundled
with scikit-learn is `sklearn.datasets.load_diabetes` — 442 rows, 10
predictors, a continuous target in `[25.0, 346.0]`. This project runs on
that dataset. **It is not house price data, and you should say so in your
own report in one sentence, the way this README does.** What makes it a
reasonable stand-in for the assignment is the *shape* of the problem, not
the subject: ten correlated numeric predictors, a continuous target with no
natural cap, and a stakeholder who wants a number with an interval attached
rather than a bare point estimate — a claims manager sizing loss reserves
instead of a buyer sizing a mortgage, but the regression discipline this
project is testing does not care which one is asking. Days 150-152 already
measured this dataset's collinearity (VIFs up to 60) and its regularization
behaviour in detail, so this project builds on numbers you can cross-check
against those days rather than starting from nothing.

**If you have a real housing CSV of your own** (a public regional dataset,
an export from a listings site you have permission to use, anything with a
numeric sale price and several numeric or one-hot predictors), you can run
every step below against it instead: replace the `load_diabetes(scaled=False)`
call with `pandas.read_csv(...)` and the rest of the pipeline — split,
scaler, ridge/lasso, VIFs, residual diagnostics — is unchanged. The
`Expected output` section below still describes the *shape* of a correct
result, and your numbers will differ far more than they would between two
diabetes runs, which is expected.

**Environment:** scikit-learn 1.9.0, NumPy 2.5.2 and scipy 1.18.1, the same
versions Days 150-153 measured their tables on. CPU only — nothing in this
project benefits from a GPU, and none is used. No network access is
required or permitted anywhere in these steps.

**Safety, because this runs on your own machine:** everything below writes
only inside your own project directory, installs nothing into system
Python, needs no `sudo`, and reaches no network. If you create a virtual
environment, create it inside your project directory or somewhere else
under your own control.

## What you are building

One small project directory whose deliverable is `REPORT.md`, generated by
a script from computed values, the same discipline Week 21's project used:

```
house-price-model/
  data/                # nothing to fetch — sklearn.datasets ships diabetes
  src/
    baseline.py          # mean-predictor baseline, computed first
    split.py               # the three-way split
    feature_analysis.py      # correlation matrix + VIFs
    regularized_model.py       # ridge + lasso, alpha by cross-validation, inside a Pipeline
    evaluate.py                  # the single test-set evaluation + interval
    residuals.py                   # residual diagnostics
    render.py                        # writes REPORT.md from computed values only
  run_project.py          # entry point: baseline -> split -> features -> model -> evaluate -> residuals -> render
  REPORT.md                  # the deliverable, generated
  manifest.json                # seed, versions, split sizes, alphas, hashes
```

A single notebook is fine on the same terms as Week 21: judged by whether
restart-and-run-all reproduces the whole thing.

## Requirements

Each traces to a specific day. Do them in order.

1. **State the target, the metric, and the baseline, before touching a
   model** (Days 148, 152). Name the target (the continuous outcome), name
   the metric you will lead with — RMSE or MAE — and defend the choice in
   one sentence: RMSE weights large errors more heavily because it squares
   them, which is the right call when a few very wrong predictions are more
   costly than many mildly wrong ones; MAE is the right call when every
   unit of error matters equally and you do not want a handful of outliers
   to dominate the number you report. Pick one as your headline metric and
   say why; you may still report the other alongside it.

2. **Compute and report the mean-predictor baseline first** (Day 152). Fit
   nothing but `y_train.mean()`. Report its RMSE and MAE on the test set,
   with a 95% interval (Requirement 7's method, applied to the baseline
   itself), before any regression model is fit. Day 152 measured that a
   model can post a high train R² using pure noise columns — the baseline
   is what keeps the rest of this project honest about what "better" means.

3. **A three-way split, with the unit of independence named** (Day 144's
   discipline, carried into regression). Say explicitly what one row
   represents in your dataset and whether any two rows could share a
   dependency a plain row-wise split would miss (repeated measurements of
   the same person, several sales of the same property). On `load_diabetes`
   each row is one patient measured once, so a plain stratified-by-nothing
   row split is correct — regression has no class to stratify on, so state
   what you did instead (a plain random three-way split) and why
   stratification does not apply here the way it did for iris.

4. **Feature analysis: a correlation matrix and VIFs, computed by you**
   (Day 150). Compute the pairwise correlation matrix on your training
   features and the variance inflation factor for every feature. Name
   which predictors are collinear (VIF meaningfully above 5-10 is the usual
   rule of thumb) and write one paragraph on what that collinearity does to
   coefficients specifically — not to predictions. Day 150 showed that
   correlated predictors can flip coefficient signs and swing their
   magnitudes wildly while the model's *predictions* stay stable; your
   paragraph should say whether your own coefficients show that pattern.

5. **A regularized model: ridge and lasso, both fitted, alpha chosen by
   cross-validation** (Day 151). Fit `RidgeCV` and `LassoCV` (or an
   equivalent manual `GridSearchCV` sweep) over a shared range of alphas.
   State the alpha each one chose. State which features lasso zeroed, if
   any, and which it kept. Day 151 measured that **ridge zeros nothing at
   any alpha** on this dataset while lasso's sparsity pattern changes with
   the penalty strength — say whether your ridge run confirms that. Then
   refit lasso under at least three different random seeds (different train
   /val/test splits) and report whether the set of kept features is stable
   or changes seed to seed. Day 151 also found that too much penalty on
   noisy data can zero out genuinely informative features, so do not treat
   "lasso zeroed more" as automatically better.

6. **Feature scaling inside a Pipeline** (Days 146, 151). The `StandardScaler`
   must be fit only on the training fold, wrapped with the regularized model
   in one `Pipeline`, for the same leakage reason Week 21 required it. State
   explicitly in your report that regularization is scale-dependent: an
   unscaled feature with large raw units (like the `s1`-`s6` serum measures
   in diabetes, or square footage in a real housing dataset) would absorb a
   disproportionate share of the penalty budget relative to a feature
   measured in small units, purely from scale, not from real importance.

7. **Exactly one test-set evaluation, with a 95% interval** (Day 144's
   discipline, applied to a continuous metric). Score your chosen
   regularized pipeline on the test set once. Report RMSE (or your chosen
   headline metric) with a 95% interval. Regression intervals do not have
   the closed-form `sqrt(p(1-p)/n)` shortcut classification does — use the
   delta-method approximation `SE(RMSE) ≈ std(squared errors) / (2 * sqrt(n)
   * RMSE)`, and show the arithmetic, not just the result. (A bootstrap
   interval — resample the test residuals with replacement, recompute RMSE
   many times, take the 2.5th/97.5th percentiles — is an acceptable
   cross-check but the delta-method number is what you report as your
   primary interval, because it is the one you can compute and verify by
   hand.)

8. **Residual diagnostics** (Day 154). Plot (or tabulate, if you are not
   producing a figure) residuals against fitted values. Check for
   curvature (a systematic bend rather than a random scatter) and for
   variance that fans out as the fitted value grows. Report the correlation
   between the residuals and the fitted values, and between the absolute
   residuals and the fitted values, as numeric evidence alongside whatever
   plot you make. Pull out the five largest-magnitude residuals by row and
   look at them individually — say what they have in common, if anything.

9. **A written verdict, 400-600 words** (the whole week, applied at once).
   State the regularized model's test RMSE (or your headline metric) and
   its interval, the baseline's, and whether the gap between them is larger
   than the two intervals combined can explain by chance. With roughly 110
   test rows on `load_diabetes`, say plainly if this is a case the
   intervals can resolve or a case where you must write "cannot
   distinguish" — do not pick a winner just because one number is smaller
   than another. Say whether the feature-selection pattern from
   Requirement 5 was stable enough to trust for a real interpretation
   ("bmi and s5 matter, age barely does") or too seed-dependent to say
   anything beyond "the model predicts reasonably well."

10. **A reproducibility artefact** (Days 126, 139, carried from Week 21).
    Pin your package versions, set and record a random seed, and rerun
    `run_project.py` (or restart-and-run-all your notebook) from a clean
    state. Confirm the split sizes, the chosen alphas, the kept lasso
    features, and the test RMSE all match between the two runs, and say in
    your report that you checked this.

## Steps

1. Load the data. If using `load_diabetes`, call it with `scaled=False` so
   your VIFs and coefficients are in real, interpretable units (age in
   years, bmi 18.0-42.2, and so on) rather than the pre-standardized version
   scikit-learn also offers. Write the target/metric/baseline paragraph
   (Requirement 1) before fitting anything.
2. Split into train/validation/test with `train_test_split` twice — once to
   carve off the test set, once to carve validation from what remains. Name
   the unit of independence (Requirement 3) here, while you are looking at
   the decision.
3. Compute the mean-predictor baseline on train; score it on the test set
   with RMSE, MAE and the 95% interval (Requirement 2).
4. On the training fold only, compute the correlation matrix and VIFs
   (Requirement 4). Write the collinearity paragraph now, before you have
   seen how any model performs — the VIF numbers should not be filtered
   through what you already know the regularized model will do.
5. Build `RidgeCV` and `LassoCV` inside `Pipeline([("scaler",
   StandardScaler()), ("model", ...)])` (Requirements 5, 6). Fit on train.
   Record the chosen alphas and lasso's kept/zeroed features. Refit lasso
   under at least three more seeds and record the kept-feature set each
   time.
6. Evaluate your chosen pipeline (ridge or lasso — pick the one with the
   better validation score, or state a reason for choosing the other) on
   the test set once. Compute RMSE, its delta-method 95% interval, and MAE
   (Requirement 7).
7. Compute residuals on the test set. Compute the two correlations from
   Requirement 8, identify the five largest-magnitude residuals, and look
   at those rows.
8. Write the 400-600 word verdict (Requirement 9), citing the actual
   numbers from steps 3, 5 and 6.
9. Move every number in `REPORT.md`'s prose into `render.py` as a formatted
   computed value. Run `run_project.py` twice from a clean state and
   confirm the results match (Requirement 10).

## Expected output

The numbers below are from one real run of this project, seeded
(`random_state=8`), on `sklearn.datasets.load_diabetes(scaled=False)` split
220 train / 111 validation / 111 test (a 50/25/25 three-way split of the
442 rows). **Your own numbers will differ with a different seed** — a
different split changes the baseline, the chosen alphas, which features
lasso keeps, and the test RMSE — but the *shapes* below (a baseline with an
interval, VIFs that separate a handful of collinear features from the rest,
a regularized model whose gain over baseline is checked against both
intervals, residuals inspected for curvature and fanning) are what a
correct report contains regardless of seed.

**Baseline.** Train-set mean target: `150.9864`. On the 111-row test set,
the mean predictor scores RMSE `75.8263`, MAE `63.1250`. Delta-method 95%
interval for RMSE: squared-error standard deviation across the 111 test
rows was `6559.29` (this is `std(squared errors)`, not RMSE itself), giving
`SE(RMSE) = (6559.29 / sqrt(111)) / (2 * 75.8263) ≈ 4.1053`, so the
half-width is `1.96 * 4.1053 ≈ 8.046` and the interval is
`75.826 ± 8.046 = [67.780, 83.873]`.

**Feature analysis.** Correlation matrix computed on the 220 training rows
shows two clearly collinear pairs: `s1` and `s2` at `r = 0.8848`, and `s3`
and `s4` at `r = -0.7434`, with several more moderate correlations around
`s4`-`s5` (`0.6146`) and `s2`-`s4` (`0.6662`). VIFs computed on the same
training rows: `age 1.2402, sex 1.4498, bmi 1.6050, bp 1.4738, s1 60.4670,
s2 42.6984, s3 14.8867, s4 9.2032, s5 12.2340, s6 1.6197`. (These are close
to, but not identical to, the whole-dataset VIFs Day 150 measured, because
these are computed on a 220-row training fold rather than all 442 rows —
say in your own report which one you computed and why a training-fold VIF
is the methodologically correct one to use for this project.) The six
serum measures (`s1` through `s6`) carry almost all of the collinearity;
`age`, `sex`, `bp` and `bmi` sit under VIF 2.

**Regularized model.** `RidgeCV` over 50 log-spaced alphas from `0.001` to
`100` (5-fold CV on the training set) chose `alpha ≈ 0.7197` and zeroed
none of the ten coefficients — consistent with Day 151's finding that ridge
does not produce exact zeros at any alpha. `LassoCV` over the same alpha
grid chose `alpha ≈ 0.1099` and, at this seed, also kept all ten features
(no coefficient closer to zero than `0.1049`, on `age`). Refitting lasso
under four more seeds shows the kept-feature set is **not stable**: seed 1
kept `{sex, bmi, bp, s2, s3, s5, s6}` (7 features, dropping `age`, `s1`,
`s4`), seed 42 kept 9 of 10 (dropping `s2`), seed 100 kept only
`{sex, bmi, bp, s1, s3, s5}` (6 features), and seed 2026 kept 8. A report
that says "lasso identified bmi, bp and the serum measures as the important
predictors" is on solid ground — those survive in every seed tried — but a
report that treats the seed-8 result of "lasso kept everything" as itself a
finding worth interpreting is overreaching: the same procedure on a
different split would have told a different, sparser story.

**Test evaluation — once.** The ridge pipeline (chosen as the headline
model; its validation RMSE was within noise of lasso's) scored RMSE
`55.6853` and MAE `44.9681` on the 111-row test set, R² `0.4606`.
Delta-method 95% interval: squared-error standard deviation `4250.34`
(`sq.errors.std()`), `SE(RMSE) = (4250.34 / sqrt(111)) / (2 * 55.6853) ≈
3.6224`, half-width `1.96 * 3.6224 ≈ 7.100`, interval
`55.685 ± 7.100 = [48.585, 62.785]`. A bootstrap check (5,000 resamples of
the test residuals) gave `[48.543, 62.626]` — close enough to the
delta-method figure to trust either.

**Baseline versus model.** The model's interval `[48.585, 62.785]` and the
baseline's `[67.780, 83.873]` do not overlap, and the point-estimate gap
(`75.826 - 55.685 = 20.14`) is roughly 2.5-3x either interval's own
half-width. This is a case the intervals can resolve: the regularized model
beats the mean-predictor baseline by more than chance on this evidence.

**Residual diagnostics.** Correlation between residuals and fitted values:
`-0.0867` (weak, no strong systematic bend). Correlation between absolute
residuals and fitted values: `0.2571` (a mild positive trend — variance
grows somewhat as predictions get larger, worth naming as a mild fanning
pattern rather than a severe one). The five largest-magnitude residuals on
the test set:

```
true=48.0  pred=203.13  resid=-155.13
true=52.0  pred=199.08  resid=-147.08
true=52.0  pred=183.34  resid=-131.34
true=276.0 pred=148.42  resid= 127.58
true=70.0  pred=175.61  resid=-105.61
```

Four of the five worst misses are the model badly overpredicting a *low*
true value (three cases of a true target near 50 predicted near 200); the
fifth is the reverse, a high true value (`276`) predicted much too low. A
concrete next step: these overpredicted-low-true rows are worth pulling
individually to check whether they share an unusual combination of
predictor values (an unusually low `bmi` paired with high serum measures,
say) that the linear model cannot represent — the kind of pattern a
from-scratch look at raw feature values would surface where the aggregate
correlation numbers above cannot.

## Troubleshooting

- **You tried `fetch_california_housing` because it sounds closer to "house
  price."** It downloads from the internet on first call, which this course
  does not permit in any lab or project. Use `load_diabetes(scaled=False)`
  instead, or your own local CSV — see the dataset note at the top of this
  README.

- **You went looking for `load_boston`.** It is gone from scikit-learn, on
  purpose, over a documented ethical problem with one of its features.
  There is no correct way to get it back inside this course; do not
  downgrade scikit-learn to find it.

- **Your lasso zeroed nothing, and you expected sparsity because that is
  "what lasso does."** Day 151 already found that the alpha `LassoCV` picks
  by cross-validation does not always zero anything on this dataset — it
  depends on the split. This project asks you to check *several* seeds for
  exactly this reason: one seed's "lasso kept everything" is not evidence
  that lasso failed, and one seed's "lasso zeroed four features" is not
  evidence those four are unimportant. Report the pattern across seeds, not
  the result of one.

- **Your VIFs do not match Day 150's table exactly.** They should not, if
  you computed yours on a training fold rather than the whole 442-row
  dataset — that is the methodologically correct choice for this project
  (Requirement 4 asks for the training fold specifically), and the two sets
  of numbers will be close but not identical. Say which one you computed.

- **You compared ridge and lasso's test scores by evaluating both on the
  test set "to see which is better."** The test set has been touched
  twice, and Requirement 7 is broken regardless of which score you keep.
  Pick your headline model using the *validation* set, before you touch
  test data at all, and report only that one pipeline's test score.

- **Your residual-vs-fitted correlation came back essentially zero and you
  are not sure what that means.** A correlation near zero between raw
  residuals and fitted values is expected and good — it means there is no
  strong systematic curvature the linear model missed. Check the
  *absolute*-residual correlation separately; that is the one that flags
  variance fanning out, and it can be meaningfully nonzero even when the
  raw-residual correlation is close to zero.

- **Your written verdict declares the regularized model "much better" than
  the baseline based on RMSE alone, with no interval check.** Compute both
  intervals and check whether they overlap before writing that sentence.
  On `load_diabetes` with roughly 110 test rows the baseline-versus-model
  gap is usually resolvable (see Expected output above), but a
  ridge-versus-lasso comparison at this sample size very often is not —
  check before claiming either.
