Two Dockerfiles for the same application. One line of source code changed.

  naive    COPY . . then install     cold 76.0s   after the edit  76.0s
  ordered  manifest, install, source cold 77.0s   after the edit   1.0s

That is the number this lab exists for: 76x, and the cold builds are within one
second of each other. Ordering the instructions costs nothing on a first build
and returns the entire install on every build after it.

The mechanism, from the plan output:

  naive    first miss line 3  COPY . .          reads changed file(s): src/app.py
  ordered  first miss line 5  COPY src/ ./src/  reads changed file(s): src/app.py

Both miss on the same file. The difference is WHERE. In the naive file the miss
happens before the install, so the install is downstream of it and re-runs. In
the ordered file the install sits above the miss and is reused.

Note what is NOT different: the same instructions, the same base image, the same
packages. Only the order.

One thing worth checking yourself. Editing README.md costs 0.0s in the ordered
Dockerfile and the full 76.0s in the naive one, because `COPY . .` reads the
README too. A file that is not part of the build still invalidates the build
when a broad copy pulls it in -- which is what .dockerignore is actually for.

The linter finds three problems in the naive file and none in the ordered one:

  line 3  copy-before-install   every source edit re-runs the install
  line 4  pip-cache-kept        no --no-cache-dir, so the wheel cache ships
  line 0  runs-as-root          no USER instruction

Line 0 means the finding is about the file as a whole rather than one line --
the absence of an instruction has no line number to point at.
