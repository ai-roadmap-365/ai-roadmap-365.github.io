# Day 144 — Train, Validation, and Test Splits

The fourth day of Course04 ("Machine Learning") and of Week 21 ("Machine
Learning Fundamentals"). It sits after Day 143, which owned the workflow,
and before Day 145, which owns overfitting and underfitting.

The through-line: **the difference between a validation set and a test set
is not the data, it is how many times you are allowed to look** — and the
cost of looking is a computable quantity rather than a warning.

The lesson opens with a thousand candidates that are literally coin flips.
The best of them scores 0.5720 on a 500-row validation set while scoring
0.4992 on a test set it never touched, and the test column does not move
at any K. It then measures the four ways a split goes wrong, ranked by
what each actually cost here: groups at 56 points, selection at 7,
temporal at 7 on average, and stratification at the point where the
evaluation stops being computable at all.

Scope boundaries, deliberately observed: Day 141 owns what a score means;
Day 142 owns the winner's curse in its bandit form; Day 143 owns stage
ordering and the rule that anything fitted is fitted on training rows;
Day 145 owns overfitting and underfitting; Day 146 owns the scikit-learn
estimator API; Day 147 assembles all of it end to end. This day uses five
splitters and three estimators without teaching any of them.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`selection-optimism-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. Its bar pairs are revealed left to right so the climb reads as
motion, and it carries a `@media (prefers-reduced-motion: reduce)` block
that leaves every bar and every printed value in its final position. Both
SVGs prefix every class, id and keyframes name — `d144a-` in the
architecture diagram, `d144f-` in the flow diagram — because an inlined
SVG's `<style>` block is not scoped to that SVG and `url(#name)` resolves
document-wide, so two diagrams on one page would otherwise restyle each
other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The test column is the control and must never be dropped.** The
  headline table's whole argument is that the validation score climbs
  while the test score does not. Presenting the validation curve alone
  would leave the climb explicable by half a dozen other causes.
- **The temporal result must keep its distribution.** The effect ranged
  from +0.0160 to +0.2557 across twenty constructions, and the first one
  tried gave +0.1428. Quoting a single seed would be the forking-paths
  problem committed inside a lesson against it. One exercise asserts the
  direction, which held 20 of 20; another asserts mean, standard
  deviation, minimum and maximum. Do not collapse them into a headline.
- **The lesson must keep ranking the four failures rather than presenting
  them as equally alarming.** Group leakage cost 56 points; temporal
  leakage cost 7 on average. Saying so is more useful than a uniform
  warning, and it is what the measurements support.
- **`sqrt(2 ln K)` is reported as overestimating, because it does.** The
  lab asserts the inequality against a simulated expected maximum rather
  than treating the closed form as truth. Do not replace the simulation
  with the formula for tidiness.
- **The 0.4112 group-aware score is below chance and that is explained,
  not hidden.** About twelve people land in that test half, each
  contributing twenty identical labels. The assertion is structural —
  below 0.5 while row-wise is far above it — rather than a value.
- Nested cross-validation, the bootstrap, out-of-bag scoring and managed
  experiment-tracking platforms are described from public documentation
  only. No output from any of them is reproduced anywhere in this lesson,
  the Alternatives section says so explicitly, and **no price is quoted**
  for the paid options.
- **This lab needs no GPU** and must stay that way. It is small-array
  NumPy and scikit-learn on the CPU, and the lab README states so.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. All nine are free to read.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d144a-` or `d144f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every code
  sample and every formula lives inside a fenced code block or backticks
  for exactly that reason; keep any addition the same way.
