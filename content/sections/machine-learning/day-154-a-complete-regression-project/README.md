# Day 154 — A Complete Regression Project

The last teaching day of Course04 ("Machine Learning") Week 22
("Regression"). It sits after Day 153, which built OLS from scratch, and
before Week 23 begins.

The through-line: **every discipline from Days 148-153 either shows up as
a measured number in one real project today, or its absence would have
changed the verdict** — and this day's own contribution is a centrepiece
no other day owns: reading the residuals themselves, not just
summarising them into one RMSE.

The lesson runs the full protocol — frame, baseline, split, sweep,
cross-validate, select, one test evaluation, residual diagnostics, a
fairness check by target level, prediction intervals, an honest verdict
with a bootstrap interval — on the diabetes-progression dataset, the only
bundled regression set in scikit-learn that needs no download. It also
reconstructs, deliberately, the mistake of selecting a model by scoring
every candidate directly on the test set, and measures that the
resulting RMSE gap is never negative across twenty seeds.

Scope boundaries, deliberately observed: Day 148 owns the one-predictor
model and its four assumptions; Day 149 owns the loss as a choice; Day
150 owns multicollinearity, measured on this exact dataset; Day 151 owns
ridge and lasso; Day 152 owns metrics that can be gamed or inverted; Day
153 owns OLS built from scratch; Day 144 and Day 147 own the three sets,
the `GatedTestSet` pattern and the leaky-selection mistake this lesson
reuses and reconstructs. This day assembles all of it and teaches none of
it again.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`leak-and-coverage-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. Its two panels of bars are revealed left to right so the sequence
of seeds reads as motion, and it carries a
`@media (prefers-reduced-motion: reduce)` block that leaves every bar and
the closing summary note in its final position. Both SVGs prefix every
class, id and keyframes name — `d154a-` in the architecture diagram,
`d154f-` in the flow diagram — because an inlined SVG's `<style>` block
is not scoped to that SVG and `url(#name)` resolves document-wide, so two
diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The target's lack of a physical unit must stay stated plainly.** The
  diabetes-progression score is a composite clinical measure with no
  named unit; every RMSE and MAE in this lesson is in that same unitless
  quantity, and no paragraph should imply otherwise.
- **The residual-diagnostics section is this day's centrepiece and must
  keep both the numbers and the honest reading of them.** The measured
  heteroscedasticity (0.2386) and curvature (-0.1278) signals are real
  but modest; reporting them as either "nothing to see" or "a serious
  problem" would both misstate the measurement.
- **The margin-vs-interval finding must keep both numbers.** The margin
  (13.9071) and the bootstrap interval ([5.5852, 22.3324]) must both
  appear together; reporting only the margin would hide that a smaller
  improvement or a smaller test set could have forced a "cannot
  distinguish" verdict instead.
- **The leaky-selection gap must be reported as a 20-seed distribution,
  including its size range.** The lab's own honesty note explains why the
  gap varies (23 real candidates, only 111 test rows); dropping that
  nuance would make the result look more uniform than it measured.
- **The fairness-by-target-level finding (ratio 1.0473) must be reported
  as the near-flat result it measured, not dramatised.** This is a real
  and valuable finding precisely because it required measuring rather
  than assuming.
- **This lab needs no GPU** and must stay that way. It is small-array
  NumPy and scikit-learn on the CPU, and the lab README states so.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. All nine are free to read.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d154a-` or `d154f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every code
  sample and every formula lives inside a fenced code block or backticks
  for exactly that reason; keep any addition the same way.
