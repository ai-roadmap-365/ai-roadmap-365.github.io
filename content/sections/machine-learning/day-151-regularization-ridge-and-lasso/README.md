# Day 151 — Regularization: Ridge and Lasso

The fifth day of Week 22 ("Regression"), in Course04 ("Machine
Learning"). It sits after Day 150, which owns the design matrix and
multicollinearity, and before Day 152, which owns choosing and reporting
regression metrics.

The through-line: **ridge and lasso are not two strengths of the same
penalty, they are two different shapes**, and the shape decides whether a
coefficient can ever land exactly on zero. Day 145 already measured that
a penalty in general trades variance for bias, at the cost of rising
training error. This day does not re-measure that trade — it measures the
contrast between the two most common penalty shapes: the constraint-region
geometry that lets an L1 penalty produce exact zeros and never lets an L2
penalty do the same, what that buys in feature selection, what it costs
when the penalty is too strong on noisy data, and the single most
practically important consequence of all of it — that regularization
requires scaled features, because the penalty is applied in whatever
units the coefficients happen to be in.

Scope boundaries, deliberately observed: Day 148 owns the one-predictor
linear model; Day 149 owns loss functions, the normal equations and
Gauss-Markov; Day 150 owns many predictors, the design matrix and
multicollinearity, and this day's correlated-predictors exercise builds
directly on it; Day 152 owns metric selection (this lesson reports R2 but
does not teach when to prefer it); Day 153 owns a from-scratch
implementation; Day 154 is the week's synthesis day.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`coefficient-path-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. Its bars fall to zero in a staggered sequence so the story reads
as motion, and it carries a `@media (prefers-reduced-motion: reduce)`
block that freezes every bar at its final, fully informative state. Both
SVGs prefix every class, id and keyframes name — `d151a-` in the
architecture diagram, `d151f-` in the flow diagram — because an inlined
SVG's `<style>` block is not scoped to that SVG and `url(#name)` resolves
document-wide, so two diagrams on one page would otherwise restyle each
other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The ridge column is the control and must never be dropped.** The
  headline table's whole argument is that ridge zeroing nothing at every
  alpha isolates the penalty shape as the cause of lasso's climbing zero
  count. Presenting the lasso curve alone would leave the climb
  explicable by half a dozen other causes.
- **The scale-dependence result must keep all three conventions.**
  Raw, standardized, and scikit-learn's own unit-L2-norm scaling select
  10, 7 and 3 features respectively at the identical alpha. Collapsing
  this to "scale your data" without the three-way disagreement between
  "scaled" conventions drops the most surprising and most actionable part
  of the finding.
- **The Ridge/ElasticNet alpha-scale mismatch is reported as measured,
  including the uncorrected failure case** (R2 0.0555 against 0.3690).
  Do not simplify this to "they're the same at l1_ratio=0" — they are not,
  until the `n_train` correction is applied, and the lab asserts the
  correction rather than assuming the naive equivalence.
- **The near-duplicate exact-zero result is reported honestly.** The
  quoted seed gives an exact `0.0`; harness check 8 found a different seed
  where lasso's dropped coefficient was `0.0007`, not a perfect zero. The
  lesson's own two-feature demonstration and headline duplicate exercise
  use the quoted seed's exact zero; the lab's cross-seed check asserts
  the weaker, honest "heavily asymmetric" claim instead. Do not silently
  upgrade that assertion to an exact zero.
- Nested topics — statsmodels' regularization support and R's glmnet —
  are described from public documentation only. No output from either is
  reproduced anywhere in this lesson, and the Alternatives section says
  so explicitly. No price is quoted for the managed AutoML alternative.
- **This lab needs no GPU** and must stay that way. It is small-array
  NumPy and scikit-learn on the CPU, and the lab README states so.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. Nine of the ten are free to read; the tenth (the original
  Tibshirani 1996 paper on JSTOR) is paywalled and is paired explicitly
  with the free Elements of Statistical Learning PDF covering the same
  method.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d151a-` or `d151f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every code
  sample and every formula lives inside a fenced code block or backticks
