# Day 146 — Your First Model with scikit-learn

The sixth day of Course04 ("Machine Learning") and of Week 21 ("Machine
Learning Fundamentals"). It sits after Day 145, which owned overfitting
and the bias-variance decomposition, and before Day 147, which assembles
everything into a full end-to-end classification exercise.

The through-line: **five methods are necessary and sufficient for direct
use, and in this version of scikit-learn, no longer quite sufficient for
full interoperability with `Pipeline` and `cross_val_score`** — a gap
found by testing, not assumed from documentation.

The lesson opens with a classifier built entirely from scratch, whose
predictions match `DummyClassifier(strategy="most_frequent")` exactly.
The same object then fails inside `cross_val_score` with an
`AttributeError` naming `__sklearn_tags__`, even though `fit`, `predict`
and `score` all still work when called directly — and one line of
inheritance from `BaseEstimator` fixes it.

Scope boundaries, deliberately observed: Day 141 owns what a score means;
Day 143 owns stage ordering, which today's `Pipeline` fit-per-fold
measurement supports mechanically rather than re-teaches; Day 144 owns
splits and `cross_val_score`'s own subject matter, used here without
re-explaining it; Day 145 owns overfitting and bias-variance, not touched
today; Day 147 owns the full end-to-end exercise. This day owns the
estimator object model itself — the thing the previous five days used
without ever explaining.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`protocol-footnote-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. Its five stages light up in sequence with a travelling token
timed to each one, so the sequence reads as motion, and it carries a
`@media (prefers-reduced-motion: reduce)` block that leaves every stage,
verdict and the caption fully legible in the static frame. Both SVGs
prefix every class, id and keyframes name — `d146a-` in the architecture
diagram, `d146f-` in the flow diagram — because an inlined SVG's `<style>`
block is not scoped to that SVG and `url(#name)` resolves document-wide,
so two diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The `__sklearn_tags__` failure and fix are the centrepiece and must
  keep both halves.** The lesson's whole argument depends on showing that
  `fit`/`predict`/`score` work directly on the bare estimator AND that the
  same object fails inside `Pipeline`/`cross_val_score`. Dropping either
  half turns the finding into either "the API is broken" or "the API
  requires BaseEstimator, full stop" — both wrong, and both weaker than
  what was actually measured.
- **`check_estimator()`'s two failures are reported by name and explained,
  never suppressed or hidden.** `check_classifiers_train` and
  `check_classifiers_regression_target` are genuine, informative failures
  given what the lab's toy estimator is; treat them as findings, not bugs
  to quietly fix away.
- **`random_state=None` numbers are never asserted as fixed values,
  anywhere.** They are fresh OS entropy on every call, by design. One real
  capture lives in the lab's `expected-output/FIELDS.md`, explicitly
  labelled as an example. The lesson and the lab both assert only the
  structural claim: identical under a fixed seed, distinct without one.
- **The estimator census (208 bare, 210 enabled, 90 transform, 119
  predict, 20 both) is scikit-learn 1.9.0-specific and must stay pinned to
  that version.** If the lab's pinned scikit-learn version changes,
  re-run the census and update every occurrence of these five numbers
  together, in the lesson, the lab and the instructor solution. Keep both
  the bare and enabled totals in the lesson — dropping either one turns a
  taught fact (discovery depends on import order) back into a single
  number a reader cannot independently verify.
- Nested cross-validation, `skorch`, `scikeras` and managed AutoML/MLOps
  platforms are described from public documentation or general knowledge
  only. No output from any of them is reproduced anywhere in this lesson,
  and **no price is quoted** for any paid option.
- **This lab needs no GPU** and must stay that way. It is small-array
  NumPy and scikit-learn on the CPU, and the lab README states so.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. All eight are official scikit-learn documentation, free to
  read.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d146a-` or `d146f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
