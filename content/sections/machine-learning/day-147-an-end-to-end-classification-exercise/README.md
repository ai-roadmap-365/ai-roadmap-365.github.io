# Day 147 — An End-to-End Classification Exercise

The seventh and last teaching day of Course04 ("Machine Learning") Week
21 ("Machine Learning Fundamentals"). It sits after Day 146, which owned
the scikit-learn estimator API, and before Day 148, which begins Week 22
(Regression) with linear regression.

The through-line: **every discipline from Days 141-146 either shows up as
a measured number in one real project today, or its absence would have
changed the verdict** — and the closing measurement of the week is that
Day 144's selection-optimism formula, applied to a real 36-candidate
sweep, predicts an inflation of 0.0326 while the measured drop over
twenty seeds averages -0.0001, because that formula assumes independent,
zero-skill candidates and these 36 are neither independent nor
skill-free.

The lesson runs the full eight-stage protocol — frame, baseline, split,
sweep, cross-validate, select, one test evaluation, error analysis,
verdict — on the Wisconsin breast-cancer dataset, chosen over iris and
wine by measuring which one gives an honest interval room to exist. It
also reconstructs, deliberately, the mistake of selecting a model by
scoring every candidate directly on the test set, and measures that the
resulting gap is never negative across twenty seeds.

Scope boundaries, deliberately observed: Day 141 owns what a score means;
Day 142 owns the winner's curse in its bandit form; Day 143 owns stage
ordering; Day 144 owns the three sets, selection optimism, and the
`GatedTestSet` pattern this lesson reuses unchanged; Day 145 owns
overfitting and underfitting; Day 146 owns the scikit-learn estimator
API. This day assembles all of it and teaches none of it again.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`optimism-comparison-flow.svg` is animated with CSS `@keyframes` inside
the file, so it animates wherever it is rendered as an image and prints
as a still. Its two panels of bars are revealed left to right so the
sequence of seeds reads as motion, and it carries a
`@media (prefers-reduced-motion: reduce)` block that leaves every bar and
the closing summary note in its final position. Both SVGs prefix every
class, id and keyframes name — `d147a-` in the architecture diagram,
`d147f-` in the flow diagram — because an inlined SVG's `<style>` block
is not scoped to that SVG and `url(#name)` resolves document-wide, so two
diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The dataset choice must stay justified by measurement, not
  assertion.** `candidate_summaries()` in the lab is the source of the
  iris/wine/breast_cancer comparison table; if that measurement changes,
  the "Choosing the dataset" subsection and the practice assignment must
  be re-checked against it.
- **The predicted-versus-measured selection-optimism finding must keep
  both numbers, and the honest explanation of the gap.** Reporting only
  the measured drop (near zero) without the prediction (0.0326) would
  make the finding look like "selection optimism doesn't matter," which
  is explicitly the wrong reading this lesson corrects for. Reporting
  only the prediction without the measurement would repeat Day 144's
  result without adding anything.
- **The leaky-selection gap must be reported as a 20-seed distribution,
  including that it is sometimes exactly zero.** The lab's own honesty
  note explains why (114 test rows are coarse); dropping that nuance
  would make the result look more dramatic, and more universal, than it
  measured.
- **The confusion matrix's clinical framing (false negatives as the
  costlier error) is a pedagogical point about reading error asymmetry,
  not a clinical claim.** Keep the "What it is — and what it is not"
  section's caution about the dataset being a decades-old teaching
  resource, not a diagnostic tool.
- Nested cross-validation, `GridSearchCV`, and managed experiment-tracking
  platforms are described from public documentation only. No output from
  any of them is reproduced anywhere in this lesson, and **no price is
  quoted** for the paid options.
- **This lab needs no GPU** and must stay that way. It is small-array
  NumPy and scikit-learn on the CPU, and the lab README states so.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. All eight are free to read.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d147a-` or `d147f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every code
  sample and every formula lives inside a fenced code block or backticks
  for exactly that reason; keep any addition the same way.
