# Day 148 — Linear Regression

The first day of Course04's Week 22 ("Regression"), opening on the model
itself: one predictor, one line, and what a fitted slope does and does
not tell you.

The through-line: **a fitted line can look completely fine on its single
summary score and still be wrong**, in four distinct, measurable ways —
and every one of those four failures is invisible in R-squared and
visible the moment you look at the residuals or a point's position.

The lesson opens with a line scoring an R-squared of 0.852 on data with
real, substantial curvature. The residuals, binned into five groups,
trace the missed curve exactly — positive, negative, negative, negative,
positive — and a quadratic fitted to those residuals explains over a
third of their own variance. It then fits BMI against a real diabetes
outcome in raw units, reads the slope as a sentence a clinician could
act on, and measures heteroscedasticity, a single high-leverage point,
and the cost of forcing the intercept to zero — each ranked by what it
actually cost here: leverage moved the slope by more than 85 percent from
one row; the forced-zero intercept cost 59 percent worse RMSE; curvature
and heteroscedasticity were both invisible in an ordinary-looking
R-squared.

Scope boundaries, deliberately observed: Week 21 owns what a model score
means, splits, overfitting, and the scikit-learn API, and this lesson
uses all of it without re-teaching it. Day 149 owns *why* squared error
specifically (the normal equations, MSE versus MAE, Gauss-Markov) — today
just fits it. Day 150 owns multiple predictors, the design matrix and
polynomial terms — today keeps to exactly one predictor. Day 151 owns
ridge and lasso; Day 152 owns metrics (R², RMSE, MAE) as a subject in
their own right, though today reports an RMSE; Day 153 owns the
from-scratch implementation of least squares — today uses scikit-learn's
`LinearRegression` throughout and does not derive it.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`four-failures-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. A token travels a pipeline through four diagnostic stage cards,
each lighting up briefly as the token arrives, and it carries a
`@media (prefers-reduced-motion: reduce)` block that halts the token at
its final position and leaves every card's colour at rest — every number
on every card is always visible regardless of animation state. Both SVGs
prefix every class, id and keyframes name — `d148a-` in the architecture
diagram, `d148f-` in the flow diagram — because an inlined SVG's `<style>`
block is not scoped to that SVG and `url(#name)` resolves document-wide,
so two diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — the harness compares the report byte
  for byte and will fail rather than let the lesson drift.
- **`load_diabetes(scaled=False)` is not optional.** Every BMI figure in
  this lesson depends on raw units; the default `scaled=True` call
  produces a different, uninterpretable slope. Do not change this without
  re-deriving every downstream number.
- **The curvature and heteroscedasticity sections must keep their
  "the R-squared looked fine" framing.** The entire pedagogical point is
  that a respectable single summary score gave no warning; softening
  0.852 or 0.5723 to look more obviously suspicious would undercut the
  lesson.
- **The leverage point's -1.3059 slope change and 26.94 leverage ratio
  must stay attached to the same fixed construction** (`leverage_dataset`
  seed 3, added point at x=40, y=5) — these are deterministic, not
  averaged, and any change to the construction changes every downstream
  number.
- **The slope-recovery table (exercise 2) is an average over 200
  replications and is reported as ranges in exercise 2b**, not exact
  ratios, because it is a sampled quantity. Do not tighten those
  tolerances without re-verifying they hold reliably.
- Do not derive *why* squared error is the right loss function anywhere
  in this lesson — that is Day 149's territory, named explicitly at the
  point where the temptation is strongest (fitting the line itself).
- Do not add a second predictor anywhere in this lesson's worked
  examples or lab — that is Day 150's territory; the informal
  extension-challenge preview is the one deliberate exception, and it is
  labelled as a preview.
- **This lab needs no GPU** and must stay that way. It is a one-predictor
  least-squares fit on at most a few thousand rows, and the lab README
  states so under Hardware requirements.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. All eight are free to read.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d148a-` or `d148f-`), keep the
  `prefers-reduced-motion` block on the flow diagram, and re-check with
  `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every code
  sample and every formula lives inside a fenced code block or backticks
  for exactly that reason; keep any addition the same way.
