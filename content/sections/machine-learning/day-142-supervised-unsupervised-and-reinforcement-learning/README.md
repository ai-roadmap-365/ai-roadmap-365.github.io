# Day 142 — Supervised, Unsupervised, and Reinforcement Learning

The second day of Course04 ("Machine Learning") and of Week 21 ("Machine
Learning Fundamentals"). It sits after Day 141, which established what a
model score does and does not mean, and before Day 143, which owns the
workflow.

The through-line: **the three settings are not three boxes of algorithms;
they are three shapes of feedback**, and every practical consequence
follows from the shape. Supervised learning is told the correct output
for every input. Unsupervised learning is told nothing, so "correct" is
undefined. Reinforcement learning is told a score for the one action it
took, never for the alternatives, and often only much later.

The lesson opens by producing two accuracy scores — 0.24 and 0.8933 — for
the identical clustering of the identical data, with the 0.6533 between
them produced by cluster numbering alone. It closes on the question that
actually decides which setting you are in, which is not whether you have
labels but whether your own actions change the data you see next.

Scope boundaries, deliberately observed: Day 141 owns the definition of
machine learning and the meaning of a score; Day 143 owns the workflow;
Day 144 owns splits and the selection bias this day only foreshadows;
Day 145 owns overfitting and underfitting; Day 146 owns the scikit-learn
API. This day uses `KMeans` and `KNeighborsClassifier` but does not teach
the estimator interface.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`reward-travels-backwards-flow.svg` is animated with CSS `@keyframes`
inside the file, so it animates wherever it is rendered as an image and
prints as a still. It carries a `@media (prefers-reduced-motion: reduce)`
block that leaves every square filled at rest, and the still frame
carries every value, every count and every conclusion. Both SVGs prefix
every class, id and keyframes name — `d142a-` in the architecture
diagram, `d142f-` in the flow diagram — because an inlined SVG's
`<style>` block is not scoped to that SVG and `url(#name)` resolves
document-wide, so two diagrams on one page would otherwise restyle each
other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The standardisation finding must not be softened.** Standardising
  before clustering is near-universal advice and it makes iris measurably
  worse: adjusted Rand index 0.6201351808870379 against 0.7302382722834697
  raw. The lesson reports the measurement, explains the mechanism (iris's
  features are already comparable centimetre lengths, so equalising them
  promotes the noisiest one), and explicitly says the right conclusion is
  not "never standardise". Do not replace it with whichever preprocessing
  happened to look better.
- **The `np.argmax` tie-breaking failure is content, not a bug to fix.**
  Both code paths stay in the library behind `break_ties_randomly`, and
  both are asserted: 0 of 300 episodes reach the goal with NumPy's
  tie-breaking and 300 of 300 with random tie-breaking. The failure is
  more instructive than the fix because it is silent.
- **The explored-log result is 7 of 8, not 8 of 8.** The single failure
  was investigated rather than reseeded away and turned out to be the
  winner's curse — the truly best arm, pulled 1524 times, losing to one
  pulled 274 times. That is a better lesson than a clean sweep and it is
  the bridge to Day 144. Do not round it up.
- **The single-split label-budget curve is not monotone** (five labels
  beat twenty) and the lab asserts that it is not. Keep it beside the
  forty-split average; the contrast is the point.
- Gymnasium, Stable-Baselines3 and managed cloud AutoML services are
  described from public documentation only. No output from any of them is
  reproduced anywhere in this lesson, the Alternatives section says so
  explicitly, and **no price is quoted** for the paid option — cloud
  pricing changes by region and by month, and an unchecked figure is
  worse than none. No edit should add one without checking it on the day.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d142a-` or `d142f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every code
  sample lives inside a fenced code block for exactly that reason; keep
  any addition the same way.
