# Day 149 — Loss Functions and Least Squares

The second day of Week 22 ("Regression"), sitting after Day 148 (the
single-predictor linear model) and before Day 150 (multiple and
polynomial regression).

The through-line: **a loss function is a choice, not a law of nature**,
and the choice decides — measurably, not just intuitively — how much
influence a single extreme data point gets over the fitted line.

The lesson opens with sixty rows, one outlier moved 80 units off an
otherwise ordinary line, and three estimators refit on the identical
corrupted data. Ordinary least squares moves 0.7545; Huber regression
moves 0.0437, seventeen times less; median regression moves 0.0104,
seventy-two times less. It then measures why: the mean minimises squared
error and the median minimises absolute error (grid search, not
citation); squared error's landscape is a smooth parabola while absolute
error's is piecewise-linear and kinked, which is exactly why squared
error has a closed form (the normal equations, solved directly and
matched to `LinearRegression` to thirteen decimal places) and absolute
error does not; Huber's epsilon parameter interpolates continuously
between the two, converging exactly to the OLS answer at large epsilon;
and the Gauss-Markov theorem's "best linear unbiased estimator" claim is
conditional on the errors — measured directly by fitting both estimators
500 times under Gaussian errors (OLS wins) and under heavy-tailed errors
(Huber wins).

Scope boundaries, deliberately observed: Day 148 owns the linear model
itself with one predictor — geometry, coefficient interpretation,
residual plots — and this lesson assumes the reader can already fit a
line. Day 150 owns multiple predictors, the design matrix and
multicollinearity. Day 151 owns ridge and lasso — a loss function plus a
penalty — and this lesson stays on plain, unpenalised losses throughout,
saying once that a penalty is coming. Day 152 owns metrics as a subject;
this lesson states the loss-versus-metric distinction exactly once and
leaves the rest to Day 152. Day 153 owns the from-scratch implementation
via gradient descent; this lesson states and uses the normal equations
but does not build a full estimator around them.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`huber-epsilon-sweep-flow.svg` is animated with CSS `@keyframes` inside
the file, so it animates wherever it is rendered as an image and prints
as a still. Its seven bars are revealed left to right so the climb toward
the OLS reference line reads as motion, and it carries a
`@media (prefers-reduced-motion: reduce)` block that leaves every bar and
every printed value in its final position. Both SVGs prefix every class,
id and keyframes name — `d149a-` in the architecture diagram, `d149f-` in
the flow diagram — because an inlined SVG's `<style>` block is not scoped
to that SVG and `url(#name)` resolves document-wide, so two diagrams on
one page would otherwise restyle each other.

  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.

  Day 151 owns penalised losses. Say a penalty is coming; do not build
  one here.
- **This lesson owns the loss-versus-metric distinction only once,
  clearly.** Do not expand it into a metrics tutorial — that is Day
  152's subject.
- **The outlier-shift table is the centrepiece and must keep all three
  estimators.** The whole argument depends on comparing OLS, Huber and
  median regression on the identical corrupted data; dropping any one of
  the three weakens the comparison the diagram and the lesson both make.

  linear, unbiased, estimator, conditional on its assumptions. Do not
  simplify it to "OLS is the best estimator."
- **The Gaussian-versus-heavy-tailed comparison must keep both
  directions.** OLS wins one and Huber wins the other; presenting only
  the heavy-tailed result would misrepresent Gauss-Markov as always
  false rather than conditional.

  converge in scikit-learn 1.9.0 before anything was built on them.** If
  you upgrade the pin, re-verify both before trusting any number that
