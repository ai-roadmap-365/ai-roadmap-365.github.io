# Day 153 — Linear Regression from Scratch

The sixth day of Week 22 ("Regression") in Course04 ("Machine Learning").
It sits after Day 152, which owned regression metrics, and before Day 154,
the week's synthesis project day.

The through-line: **the textbook formula for linear regression is not what
a good library actually runs, and the gap is measurable.** Ordinary least
squares is built three separate ways — the normal equations, an
`lstsq`-based solve, and gradient descent — wrapped in a real
scikit-learn-compatible estimator, and measured against `LinearRegression`
itself to find out exactly where the library's default choices earn their
keep.

The lesson opens with a design matrix carrying one near-duplicate column:
true coefficients `[1, 2, 3, 4]`, and the textbook formula returns
`196747.976` where the answer is `1`. It then traces the mechanism —
`cond(X'X)` is exactly the square of `cond(X)`, confirmed to ten decimal
places on well-conditioned data — applies Day 111's gradient-descent
stability formula to a real Hessian and predicts a divergence boundary to
the decimal, and runs the real `sklearn.utils.estimator_checks.check_estimator`
suite against a from-scratch estimator, reporting 48 of 52 checks passing
and naming the two that do not.

Scope boundaries, deliberately observed: Day 111 owns gradient descent
itself and is cited, not re-derived; Day 146 owns the scikit-learn
estimator API contract and is cited, not re-taught; Day 148 through 152
own what a fitted coefficient means, the loss function, many predictors,
regularization and metrics, and are assumed as background; Day 150's
multicollinearity is the statistical description this lesson measures as
a numerical-precision problem.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`stability-threshold-flow.svg` is animated with CSS `@keyframes` inside
the file, so it animates wherever it is rendered as an image and prints
as a still. Its two lanes reveal their travelling tokens on a seven-second
loop, and it carries a `@media (prefers-reduced-motion: reduce)` block
that leaves both tokens at the end of their paths — settled beside the
target in the converging lane, off-frame in the diverging one. Both SVGs
prefix every class, id and keyframes name — `d153a-` in the architecture
diagram, `d153f-` in the flow diagram — because an inlined SVG's
`<style>` block is not scoped to that SVG and `url(#name)` resolves
document-wide, so two diagrams on one page would otherwise restyle each
other.

  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The near-duplicate-column case is the centrepiece and must keep its
  three-way contrast.** Presenting only the normal equations' explosion,
  without lstsq's parallel explosion and sklearn's sane answer beside it,
  would leave the argument about numerical stability rather than a
  library implementation detail unsupported.
- **The `cond(X'X) = cond(X)^2` relationship must be reported both where
  it holds exactly (1.0000000000 on the diabetes data) and where its
  verification degrades (0.9527 on the dramatic case), with the honest
  explanation that the theorem, not its numerical measurement, is what
  remains exact.** Do not round the 0.9527 case to 1.0 for tidiness.
- **No wall-clock timing appears anywhere in the operation-count
  comparison.** The closed form versus gradient descent comparison uses
  formula-derived operation counts specifically because they are
  reproducible on any machine; a timing figure would not be, and the lab's
  `report_measurements.py` never calls a clock.
- **The Day 111 citations must remain citations, not re-derivations.**
  Gradient descent's update rule, the stability condition
  `|1 - eta * a| < 1`, and the condition number as a ratio of Hessian

  real Hessian and reports the measurement, and should not re-derive the
