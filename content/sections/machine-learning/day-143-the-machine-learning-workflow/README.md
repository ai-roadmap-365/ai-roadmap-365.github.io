# Day 143 — The Machine Learning Workflow

The third day of Course04 ("Machine Learning") and of Week 21 ("Machine
Learning Fundamentals"). It sits after Day 142, which named the three
learning settings, and before Day 144, which owns train, validation and
test splits.

The through-line: **a workflow is not the list of its stages; it is the
connections between them** — and one wrong connection is worth
twenty-three accuracy points on data that contains nothing to learn.

The lesson opens with the same pipeline run twice on identical data, with
the identical model, folds and seed, reporting 0.5000 in the correct order
and 0.7300 with `select` and `split` transposed. No exception, no warning,
no NaN. It then shows a declared stage contract turning that silent lie
into a `StageContractError` naming the stage that broke and the key it
wanted.

Scope boundaries, deliberately observed: Day 141 owns what a score means;
Day 142 owns the three settings, which is this day's framing stage; Day
137 owns leakage as a concept, while this day owns the *ordering* that
produces it; Day 144 owns splits, cross-validation design and
model-selection bias; Day 145 owns overfitting and underfitting; Day 146
owns the scikit-learn estimator API. This day uses `Pipeline`,
`StratifiedKFold` and four estimators without teaching any of them.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`two-orderings-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. Its two tokens travel in sequence rather than at once, so the two
runs are seen one after the other. It carries a
`@media (prefers-reduced-motion: reduce)` block that rests both tokens at
the end of their tracks, and the still frame carries both orderings, both
scores and the error text. Both SVGs prefix every class, id and keyframes
name — `d143a-` in the architecture diagram, `d143f-` in the flow diagram
— because an inlined SVG's `<style>` block is not scoped to that SVG and
`url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too — check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The 0.50 against 0.73 comparison is the spine of the day and must
  keep its controls.** The two runs share data, model, folds and seed;
  the step logs differ by exactly one transposition. Any edit that
  weakens those controls destroys the argument, because the whole claim
  is that nothing else changed.
- **The contract's limitation must stay stated.** The `select` stage in
  `leaky_stages()` declares `folds` honestly, and the lesson says plainly
  that a team declaring `requires=("X", "y")` defeats the check entirely.
  The value claimed is that a contract turns an implicit ordering into a
  reviewable claim — not that it makes wrong claims impossible. Do not
  upgrade that claim.
- **The below-chance scores are not to be tidied away.** Two honest
  scores in the inflation table are 0.39 and 0.38. That is 20 test rows
  per fold and a standard error near 0.11, and the lab asserts
  `right <= 0.5` rather than `right == 0.5` for exactly that reason. The
  lesson explains it rather than reseeding until it looks neat.
- **The 30 percent is an upper bound, not an estimate, and is measured
  from this lab's own source** with `inspect.getsource`. The familiar
  folklore percentages disagree with each other and none could be
  verified here, so none is quoted. If you edit `workflow_lib.py` the
  counts legitimately change and the assertion must change with them.
- **The manifest hashes move with the NumPy pin.** The version-independent
  property is that two runs at one seed agree and two seeds do not; the
  literal hashes are kept only as a drift detector on this machine, and
  `expected-output/FIELDS.md` says so.
- Kedro, Metaflow, Prefect and managed MLOps platforms are described from
  public documentation only. No output from any of them is reproduced
  anywhere in this lesson, the Alternatives section says so explicitly,
  and **no price is quoted** for the paid options — cloud pricing changes
  by region and by month, and an unchecked figure is worse than none.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d143a-` or `d143f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` — MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every code
  sample lives inside a fenced code block for exactly that reason; keep
  any addition the same way.
