# Day 152 — Regression Metrics

The fifth day of Week 22 ("Regression") in Course04 ("Machine Learning").
It sits after Day 151, which owned ridge and lasso regularisation, and
before Day 153, which owns the from-scratch implementation.

The through-line: **Day 149 drew the line once -- a loss is what you
optimise, a metric is what you report, and they do not have to be the same
function.** This day owns the reporting side completely: RMSE, MAE, MAPE,
R-squared and adjusted R-squared, what each one means, what unit it is in,
what it hides, and when each is the wrong thing to quote. The centrepiece
is R-squared, because it is the most quoted and least understood number in
regression.

The lesson opens with a linear model's training R-squared climbing from
0.5554 to 0.7403 as columns of pure random noise are added -- columns
with exactly zero relationship to the target. It measures adjusted
R-squared correcting that climb at a modest predictor count and breaking
down itself once the predictor count approaches the row count. It measures
that R-squared has no lower bound (a deliberately bad predictor scores
-4.7009). It measures RMSE moving 11.39 times against MAE's 3.00 times
under one outlier. It breaks MAPE at a zero true value (a silent,
non-raising failure) and states its real, narrower structural asymmetry.
And its single most useful measurement is a genuine ranking inversion:
two models, scored on the same targets, where RMSE prefers one and MAE
prefers the other.

Scope boundaries, deliberately observed: Day 148 owns the one-predictor
linear model and residual plots; Day 149 owns the loss functions
(MSE/MAE/Huber as things you optimise) and the loss/metric distinction,
stated once and handed off explicitly to this day; Day 150 owns multiple
predictors and multicollinearity; Day 151 owns ridge and lasso; Day 153
owns the from-scratch implementation; Day 154 is the synthesis day. This
day owns what you report, and why the choice is not the same as the loss.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links -- to the lab and to neighbouring days --
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`outlier-metric-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. Its token travels each of two paths and the resulting bars grow
into view over a seven-second loop, and it carries a `@media
(prefers-reduced-motion: reduce)` block that leaves both tokens grown to
their final size and both bars at their final height with their final
labels visible. Both SVGs prefix every class, id and keyframes name --
`d152a-` in the architecture diagram, `d152f-` in the flow diagram --
because an inlined SVG's `<style>` block is not scoped to that SVG and
`url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler -- if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-27, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too -- check 6 of the harness compares the
  report byte for byte and will fail rather than let the lesson drift.
- **The adjusted-R2 breakdown at 100 noise columns must never be softened
  into "adjusted R2 always corrects overfitting."** The measured fact is
  that it corrects at a modest predictor count and fails at a high one;
  presenting it as an unconditional fix would misstate what was measured.
- **The MAPE-asymmetry claim must keep its narrower, verified form.** A
  direct construction showed that equal-magnitude errors on a fixed true
  value produce IDENTICAL MAPE in either direction -- the looser folklore
  claim that over- and under-prediction are scored unequally does not hold
  under that construction. The verified claim is structural: under-
  prediction is bounded at 100 percent, over-prediction is not. Do not
  restate the looser folklore version as fact.
- **The diabetes target has no physical unit**, and the lesson must not
  invent one (no "mg/dL", no fabricated real-world unit). State plainly
  that RMSE and MAE are in "points on the target's own 25-346 scale."
- **The RMSE-versus-MAE ranking inversion is the centrepiece measurement
  after R2** and must keep both models' both metrics stated together --
  presenting only one metric's preference would understate the point.
- Nested topics not measured here -- symmetric MAPE, quantile loss as a
  metric, Huber-based reporting -- are described from public documentation
  only where mentioned, and no output from them is reproduced anywhere in
  this lesson.
- **This lab needs no GPU** and must stay that way. It is small-array
  NumPy and scikit-learn on the CPU, and the lab README states so.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. All eight are free to read.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact -- the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d152a-` or `d152f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{` or `<` in prose anywhere in `index.mdx` -- MDX
  parses `{` and `}` as JSX and `<` as the start of a tag. Every formula
  lives inside a fenced `text` code block for exactly that reason; keep
  any addition the same way.
