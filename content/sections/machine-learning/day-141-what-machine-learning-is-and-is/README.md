# Day 141 — What Machine Learning Is and Is Not

The first day of Course04 ("Machine Learning"), the first day of Week 21
("Machine Learning Fundamentals"), and the reader's first day of machine
learning after 140 days of computing foundations, Python, probability,
statistics and data analysis. It sits after Day 140, the Course03
project, and before Day 142, which owns the supervised/unsupervised/
reinforcement taxonomy.

The through-line: **machine learning is function approximation from
examples, and everything that makes it useful or dangerous follows from
that one sentence.** The lesson opens by dismantling accuracy — a
one-nearest-neighbour model fitted to coin-flip labels scores exactly
1.000 on its training data and 0.518, chance, on unseen data — and then
spends the rest of the day on what the subject is not: not reasoning,
not understanding, not causal inference, not a database lookup, and not
a substitute for a rule you could write down.

Scope boundaries, deliberately observed: Day 142 owns the learning-type
taxonomy, Day 143 the workflow, Day 144 train/validation/test splits,
Day 145 overfitting and underfitting, and Day 146 the scikit-learn API.
This day uses scikit-learn but does not teach it — every model is built
by a one-line helper with its hyper-parameters already fixed.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`memorise-vs-generalise-flow.svg` is animated with CSS `@keyframes`
inside the file, so it animates wherever it is rendered as an image and
prints as a still. It carries a `@media (prefers-reduced-motion: reduce)`
block that disables every animation and restores the resting state, and
the still frame carries the whole meaning on its own. Both SVGs prefix
every class, id and keyframes name — `d141a-` in the architecture
diagram, `d141f-` in the flow diagram — because an inlined SVG's
`<style>` block is not scoped to that SVG and `url(#name)` resolves
document-wide, so two diagrams on one page would otherwise restyle each
other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections,
  no filler — if a fact or figure is not verified, leave it out rather
  than approximating it.
- **Every number in this lesson is captured from a real run** on the
  authoring machine on 2026-08-24, using numpy 2.5.2, scikit-learn 1.9.0
  and pytest 9.1.1 in the lab's own lab-local virtual environment. If
  you change a number here, re-run the capture and change it in the
  lab's `expected-output/` directory too. The lab's
  `expected-output/FIELDS.md` separates the four values that are exact
  everywhere by arithmetic (the 1-NN's 1.000, the 0.900 baseline, the
  0.750 ceiling and the rule's 1.000) from the twenty-one that are exact
  only under those pins.
- **The "1-NN training accuracy is 1.000 by construction" claim carries a
  measured exception and it must not be dropped.** A 1-NN misses a
  training row when two identical feature rows carry different labels,
  and iris contains exactly one duplicated feature row — positions 101
  and 142, `(5.8, 2.7, 5.1, 1.9)`. Both carry class 2, so on iris's real
  labels 1-NN still scores 1.000; permute the labels and the same pair
  drops it to 149 out of 150. Exercise 1b measures this rather than
  asserting the tidier and false claim.
- **The exercise 8 finding is 2.1 points, not zero, and must not be
  rounded down.** More data does help a noise-limited model a little,
  because n=200 is a small sample; what it cannot do is cross the
  ceiling. The lesson reports the 2.1 alongside the 39.8 and asserts the
  contrast rather than a false flatness.
- XGBoost and managed cloud AutoML services are described from public
  documentation only. No output from either is reproduced anywhere in
  this lesson, the Alternatives section says so explicitly, and **no
  price is quoted** for the paid option — cloud pricing changes by
  region and by month, and an unchecked figure is worse than none. No
  edit should add one without checking it on the day.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere
  in the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and
  keep the exact H2 heading strings intact — the lesson validator checks
  them. Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d141a-` or `d141f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX and no bare `{`/`<` in prose anywhere in `index.mdx` — MDX
  parses `{`/`}` as JSX and `<` as the start of a tag. Every code sample
  and every range like the training interval in the extrapolation
  section lives inside a fenced code block for exactly that reason; keep
  any addition the same way.
