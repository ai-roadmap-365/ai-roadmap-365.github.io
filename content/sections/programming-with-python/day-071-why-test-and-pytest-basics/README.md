# Day 071 — Why Test, and pytest Basics

The opening lesson of Week 11 ("Testing and Code Quality"), and the first day
in the course that installs a third-party tool. It answers the question Day 70
left hanging — you have just built a domain model you cannot re-check by hand,
so what now? — by building testing up from nothing: a test is arrange, act,
assert; a bare `assert` in a script is already a test suite with a
machine-readable result; and pytest is an amplifier for that idea rather than a
new one. From there the lesson walks the whole anatomy of a run (rootdir,
`conftest.py`, collection, assertion rewriting, execution, reporting, exit
code), teaches the output and the six flags that matter, and ends on the point
the week is built around: a test that passes no matter what the code does is
worse than no test, and the only way to know which kind you have is to watch it
fail on purpose. It sets up fixtures (Day 72), mocking at the boundary
(Day 74), type checking (Day 75), and linting (Day 76).

cross-links (to the lab, to neighboring days) are generated by the layout from
central configuration — never hard-code repository or site URLs inside content
