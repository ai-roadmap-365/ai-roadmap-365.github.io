# Day 098 — Section Project: A Complete Data Pipeline

The final day of Week 14 and the Course 02 section project. Days 78 to 97 taught
the parts — HTTP and retries, CLIs, scheduling, packaging, the automation
toolkit, SQL and schema design, the non-relational trade-offs, SQLAlchemy,
pydantic, time zones, concurrency, and logging and configuration. This day is
the assembly, and its job is to make the reader *feel* that the pieces fit.

The through-line: **a pipeline is not a script that moves data; it is a set of
promises about what happens when something goes wrong.** Every stage is a place
where the run can fail, and the design question at each one is "what does this do
at 3 a.m. when nobody is watching?"

Five stages, five promises, each traced back to the day it came from:

1. **Ingest** (Days 78, 84) — a deadline on every fetch, retry only what is worth
   retrying, and partial success reported as a value rather than raised.
2. **Validate** (Day 94) — a pydantic gate that collects every bad record with a
   field path and a reason, counts the reasons, and never ends the run.
3. **Store** (Days 88, 91, 93) — an idempotence key, enforced in two layers, so
   running twice stores once.
4. **Report** (Days 86, 91, 95) — the report instant as a parameter, not a clock
   reading.
5. **Observe** (Days 81, 97) — one structured log line per stage, a run id
   threaded through, configuration provenance printed, and three exit codes.

Underneath all five: **idempotence as the property that makes everything else
recoverable.** If a run can be repeated safely, almost every failure becomes
"run it again".

The day's sharpest demonstration is the two-layer idempotence argument, and it is
a measurement rather than an assertion. Removing only the application-level
pre-check — leaving the `UNIQUE` constraint in place — leaves the table with
exactly the right six rows while the log claims six inserts where it made none.
The database was never wrong; the pipeline was lying about its own work. Six of
the lab's 84 checks fail on that change, and not one of them is a check on the
data.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with it:
the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata and time estimates.
Images are referenced from `index.mdx` with relative paths into `assets/`, and
their alt text must stay identical to `visuals.yml`. All cross-links — to the lab
and to neighbouring days — are generated by the layout from central
configuration; never hard-code repository or site URLs inside content files.

`pipeline-run-flow.svg` is animated with CSS `@keyframes` inside the file, so it
animates wherever it is rendered as an image and prints as a still. It carries a
`@media (prefers-reduced-motion: reduce)` block that disables every animation and
restores the resting state, and the still frame carries the whole meaning on its
own — every count, every wire and every label is present without motion. Both
SVGs prefix every class, id and keyframes name — `d098a-` in the architecture
diagram, `d098f-` in the flow diagram — because an inlined SVG's `<style>` block
is not scoped to that SVG and `url(#name)` resolves document-wide, so two
diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no filler
  — if a fact or figure is not verified, leave it out rather than approximating
  it.
- **Every number in this lesson is captured from a real run** on the authoring
  machine on 2026-08-16, offline, against a fixture server bound to 127.0.0.1.
  The captures live in the lab's `expected-output/` directory and are compared
  byte for byte by section 9 of `tests/run_tests.sh`. If you change a number
  here, re-run the lab and re-capture there too.
- The environment facts are specific and were observed, not assumed: macOS
  26.5.2 on Apple Silicon, Python 3.14.0, SQLAlchemy 2.0.51, pydantic 2.13.4,
  SQLite 3.53.3, pytest 9.1.1, bash 3.2.57. Re-verify before changing any version
  claim.
- **Airflow, Dagster, Prefect and dbt are described from their documentation
  only.** No output, benchmark, price, tier limit or free-tier allowance is
  reproduced for any of them, and the lesson says so plainly. Section 1 of the
  lab's harness asserts that none of them is importable, so the claim cannot go
  quietly stale. Keep it that way.
- The two-layer idempotence demonstration is the load-bearing argument of the
  store half, and the number that carries it is that `total_rows` stays correct
  while `inserted` goes wrong. Do not soften that into "you should also
  pre-check".
- The valid-but-wrong record is stored and flagged, never dropped, and the
  lesson argues for it. Do not turn that into a validation rule.
- The report instant is a parameter with the three benefits stated —
  testability, backfill, incident timeline. Preserve all three; people usually
  only see the first.
- Temperature is an integer count of deci-Celsius throughout, and the division
  by ten happens at the display edge and nowhere else. Do not introduce a float
  into the schema.
- The concurrency section states where concurrency pays *and why it does not pay
  elsewhere*, and says plainly that the lab kept the fetch sequential by choice.
  Do not rewrite that into a recommendation to parallelise.
- All station names, readings and the API token are invented. `demo-token-value`
  is not a credential for anything; it exists so a redaction test has something
  real to redact. Keep any replacement equally obviously fictional.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the
  content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the
  exact H2 heading strings intact — the lesson validator checks them. Alt text
  must contain no square brackets: a closing bracket ends markdown image syntax
  and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind its
  file's prefix (`d098a-` or `d098f-`), keep the `prefers-reduced-motion` block,
  and re-check with `xmllint --noout`.
