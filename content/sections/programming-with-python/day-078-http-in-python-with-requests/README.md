# Day 078 — HTTP in Python with requests

The first lesson of Week 12 ("Python for Automation and the Web"), and the day
the learner's program stops being alone on their machine. Every lab before this
one read a local file and printed something. This one asks another process for
data over a network protocol, and everything that makes distributed systems
hard arrives at once: a call that might never return, a server that says no, a
server that says "not now", a body too large for memory, and a status code
meaning failure delivered inside a request that succeeded perfectly.

The lesson covers HTTP itself properly before it covers the library — the real
bytes of a request and a response shown at least once, methods and what they
promise about safety and idempotence, status codes by family and by name,
headers that matter, and query-string encoding — then `requests`: `Session`,
`timeout`, `.text` versus `.content` versus `.json()`, `raise_for_status`,
retries with exponential backoff and jitter, streaming, and credentials from
the environment.

Its spine is the continuity argument. Week 11 taught testing, and Day 74 in
particular argued that you inject a boundary rather than patch it. The network
is the canonical boundary, so this is the day that argument becomes concrete: a
function that takes a `session` parameter can be tested with a forty-line fake
and no server at all, and the lab proves it by copying the client into an empty
directory with no server in it and running twenty passing tests there.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata, and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay in sync with `visuals.yml`. All
cross-links (to the lab, to neighboring days) are generated by the layout from
central configuration — never hard-code repository or site URLs inside content
files.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no filler of any kind — if a fact or figure is not verified, leave it out rather than approximating it.
- **Every code output shown in the lesson is captured from a real run on the authoring machine** (macOS 26.5.1, Python 3.14.0, requests 2.34.2, pytest 9.1.1, httpx 0.28.1, 2026-07-19), against the lab's local test server on 127.0.0.1. **Nothing quoted here was produced by a request to the internet.** If the lab code changes, re-run it and replace the captured text rather than editing the numbers by hand.
- The port numbers visible in captured output (for example `127.0.0.1:54037`) differ on every run, because the lab binds port `0` and the operating system assigns one. That is deliberate and must not be replaced with a fixed port.
- The HTTP/2 discussion in the Alternatives section is deliberately hedged: the `httpx[http2]` extra was **not** installed on the authoring machine, so no HTTP/2 claim here rests on a local measurement. Keep that hedge if you edit it.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the content.
- When you revise any file in this directory, update `last_verified` in `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, character for character, and keep the exact H2 heading strings intact — the lesson validator checks both.
- Alt text must contain no square brackets: a closing bracket terminates markdown image syntax and the alt renders broken.
- Regenerate any downstream exports (search index, print/PDF builds) after edits so rendered outputs match the source.
