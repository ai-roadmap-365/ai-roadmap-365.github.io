# Day 079 — Web Scraping Responsibly

The second lesson of Week 12 ("Python for Automation and the Web"). Day 78
taught HTTP and `requests`; this day takes the next step — reading a page that
was written for a human — and spends its first half on the question of whether
to write the program at all. The word "responsibly" in the title is earned
rather than appended: `robots.txt` and `urllib.robotparser`, crawl delay,
terms of service as a contract question, rate limiting and backoff, honest
identification, personal data, copyright, and a plain statement that the legal
position varies by jurisdiction and by case, all arrive before the first CSS
selector. The alternatives you should exhaust first — an API, a data dump, an
RSS feed, a sitemap, or simply asking — come next. Only then does the lesson
cover BeautifulSoup, selectors, missing elements, pagination, caching and the
maintenance argument. The AI thread is drawn explicitly: training corpora and
retrieval indexes are assembled by crawling, so the provenance, licensing and
consent questions here are the same ones that return later as dataset
governance.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata, and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay in sync with `visuals.yml`. All
cross-links (to the lab, to neighboring days) are generated by the layout from
central configuration — never hard-code repository or site URLs inside content
files.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no filler of any kind — if a fact or figure is not verified, leave it out rather than approximating it.
- Every code output shown in the lesson is captured from a real run of the Day 79 lab against its local fixture server. Nothing in this lesson was run against a live third-party site, and no output is quoted for a tool that is not installed here. If the lab changes, re-run it and replace the captured text rather than editing the numbers by hand.
- The Alternatives section names four tools that are not installed on the authoring machine (`lxml`, `selectolax`, Scrapy, Playwright). Describe them from their documented behaviour and never quote output or benchmark numbers for them.
- Nothing in this lesson may hard-code a port. The lab's server binds port 0, and the lesson refers to "the local test server" or uses a `base` variable.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the content.
- The legal material must stay hedged and jurisdiction-neutral, must name no specific case or company, and must keep the explicit statement that it is not legal advice.
- When you revise any file in this directory, update `last_verified` in `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the exact H2 heading strings intact — the lesson validator checks them. Alt text must contain no square brackets.
