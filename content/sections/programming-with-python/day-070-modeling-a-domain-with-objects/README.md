# Day 070 — Modeling a Domain with Objects

The capstone lesson of Week 10 ("Files, Errors, and Objects"). It turns the
week's parts — files, CSV and JSON, exception strategy, classes, composition
and the dunder protocols, dataclasses and type hints — into a *method*: write
the domain in plain sentences, extract the nouns and verbs, separate entities
from value objects, name every invariant and its enforcement point, draw the
boundary between a pure core and its adapters, model relationships with
composition, hide storage behind a repository, and express refusals as a
domain exception hierarchy. It is the object-oriented counterpart to Day 63
(designing a small program well), and the direct rehearsal for the Week 10
project, the Expense Tracker — which is why the lesson's running example is
deliberately a spending tracker while the lab models a different domain.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata, and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay in sync with `visuals.yml`. All
cross-links (to the lab, to neighboring days) are generated by the layout
from central configuration — never hard-code repository or site URLs inside
content files.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no filler of any kind — if a fact or figure is not verified, leave it out rather than approximating it.
- Every code output shown in the lesson is captured from a real run; if the example code changes, re-run it and replace the captured text rather than editing the numbers by hand.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the content.
- When you revise any file in this directory, update `last_verified` in `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the exact H2 heading strings intact — the lesson validator checks them.
- Keep the lesson's running example (a spending tracker) distinct from the lab's domain (gym membership); the separation is deliberate so the Week 10 project stays a fresh exercise.
- Regenerate any downstream exports (search index, print/PDF builds) after edits so rendered outputs match the source.
