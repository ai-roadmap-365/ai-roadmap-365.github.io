# Day 075 — Static Typing with mypy

The fifth lesson of Week 11 ("Testing and Code Quality"). Day 69 taught type
annotations and had to make an explicit honesty call: no type checker was
installed on the authoring machine, so that lesson quoted no checker output at
all and instead proved by runtime inspection that Python stores annotations
and ignores them. **mypy is now installed — version 2.3.0 (compiled: yes),
verified 2026-07-19 alongside Python 3.14.0 — and this lesson is the payoff.**
It opens by closing that loop explicitly, then covers the two-worlds model,
gradual typing and PEP 484, running mypy with real captured output, reading an
error by its bracketed error code, the type system at working depth (builtin
generics, `Optional`/`X | None`, `Union`, `Any`, `TypeVar`, `Protocol`,
`Literal`, `TypedDict`, `Final`, `NewType`, `cast`), narrowing, configuration
in `pyproject.toml`, responsible use of `# type: ignore[code]`, typing
third-party code via typeshed and stubs, incremental adoption, and the honest
limits — closing on the sentence the week turns on: types and tests catch
different bug classes, and Day 77 assembles both.

  rather than approximating it.
- **Every line of checker output in this lesson is a real capture from a real
  run of mypy 2.3.0 on 2026-07-19.** Some come from the lab's
  `expected-output/sample-run.txt`; the rest come from short files run
