# Day 099 — Vectors: Direction, Magnitude, and Meaning

The first lesson of **Course 03 (Math, Statistics, and Data)** and of Week 15
("Linear Algebra I: Vectors and Matrices"). It is also the first mathematics
in the course, arriving after 98 days of computing and Python.

That audience shapes everything here. The reader has written real programs and
has, in many cases, decided in advance that they are not a mathematics person.
So the lesson does not open with a definition or with notation. It opens with
something they have already been using without the name: **a row of numbers
describing one thing** — a house with three numbers, a colour with three
channels, a user with a hundred behaviour counts. Only then does it say that
this is a vector, and that an embedding is exactly this.

The through-line: **"similar things are near each other" is a claim about
distance, and by the end of the day you can compute it.** Everything the
lesson introduces — components, magnitude, the L2 norm, unit vectors,
subtraction — exists to make that sentence checkable, and the day ends with a
worked embedding table where six short articles get four hand-made numbers
each and the nearest pair falls out of the arithmetic.

Two secondary threads matter as much as the vector algebra. The first is that
every worked number is re-derivable with a pen: the squares, the sum, the
square root, all shown. The second is that **floating-point comparison is
part of the subject, not an implementation detail** — a normalised vector's
magnitude is not exactly `1.0`, and the lab's tests use a stated tolerance for
that reason, which is Day 46 being paid off.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay identical to `visuals.yml`. All
cross-links are generated by the layout from central configuration; never
hard-code repository or site URLs inside content files.

`vector-operations-flow.svg` is animated with CSS `@keyframes` inside the
file, carries a `@media (prefers-reduced-motion: reduce)` block that restores
the resting state, and reads completely as a still picture — the coordinates
and the arithmetic are drawn, not merely animated into view. Both SVGs prefix
every class, id and keyframes name (`d099a-`, `d099f-`), because an inlined
SVG's `<style>` is not scoped to that SVG and `url(#name)` resolves
document-wide.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no filler — if a fact or figure is not verified, leave it out rather than approximating it.
- Every output shown in this lesson is captured from a real run on the authoring machine on 2026-08-16, with NumPy 2.5.2. The captures live in the lab's `expected-output/` directory; if you change a number here, re-run the lab and change it there too.
- **Every worked example must remain re-derivable by hand.** This is the first mathematics lesson in the course and its audience is deliberately protected: show the squares, the sum and the root, and prefer numbers whose answer is exact (a 3-4-5 triangle) over numbers that are merely realistic.
- Do not introduce notation without defining it at first use, and do not assume familiarity with any symbol beyond school arithmetic.
- The floating-point point is load-bearing, not an aside: a normalised vector's magnitude is not exactly 1.0, the tests use a tolerance, and the lesson says why. Do not "tidy" that into an exact comparison.
- NumPy is the only third-party library run here. PyTorch, JAX and pandas are described from documentation with no output reproduced — keep it that way unless you install one and capture a real run.
- The six articles in the embedding example and their four hand-made numbers are invented for the exercise and are stated to be invented. Keep any replacement equally obviously fictional.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the content.
- When you revise any file in this directory, update `last_verified` in `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the exact H2 heading strings intact — the lesson validator checks them. Alt text must contain no square brackets: a closing bracket ends markdown image syntax and the image renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind its file's prefix (`d099a-` or `d099f-`), keep the `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
