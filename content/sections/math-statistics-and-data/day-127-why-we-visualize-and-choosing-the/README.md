# Day 127 — Why We Visualize, and Choosing the Right Chart

The first day of Week 19 ("Data Visualization"), opening Course 03's
`data-analysis` subsection into the visual half of analysis after Week 18
closed pandas. The week's project is an Exploratory Analysis Report, and
this day supplies the decision procedure that report's charts are chosen
with.

The through-line: **a chart is an argument, and the encoding is the
claim.** The lesson opens with eight regions and one question — which grew
fastest? — drawn twice from identical, equally honest numbers: once as a
pie chart, once as a sorted horizontal bar chart. The bar chart answers in
under a second; the pie chart cannot be read that way at all, because
judging angle and area is something human vision is measurably bad at.
From there the lesson builds the Cleveland-McGill accuracy ordering as a
decision procedure, the square-law distortion of radius-scaled size
encoding, a working question-to-chart decision table, the four data types
and which channels can carry each honestly, colour treated seriously
(sequential, diverging and categorical palettes, and red-green deficiency
measured rather than asserted), the case where a table beats a chart,
small multiples against overplotting, pre-attentive attributes, and
data-ink without dogma.

Deliberately out of scope, because neighbouring days own them: Day 116
already showed Anscombe's quartet and is referenced in one sentence rather
than re-told; Day 128 owns matplotlib mechanics; Day 132 owns chart
honesty — truncated axes and misleading scales — which is a different
failure from today's, since every failure in this lesson is committed with
an honest axis and a complete dataset.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days — are
generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`chart-choice-flow.svg` is animated with CSS `@keyframes` inside the file,
so it animates wherever it is rendered as an image and prints as a still.
It carries a `@media (prefers-reduced-motion: reduce)` block that disables
every animation and restores the resting state, and the still frame
carries the whole meaning on its own — the rejected branches, the size
gate, the recommendation and the struck-through pie chart are all present
without motion. Both SVGs prefix every class, id and keyframes name —
`d127a-` in the architecture diagram, `d127f-` in the flow diagram —
because an inlined SVG's `<style>` block is not scoped to that SVG and
`url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every number shown in this lesson is captured from a real run on the
  authoring machine on 2026-08-20, using matplotlib 3.11.1, seaborn
  0.13.2, NumPy 2.5.2 and Pillow 12.3.0 in the lab's own `.venv`. The
  captures live in the lab's `expected-output/` directory, and
  `expected-output/measurements.txt` prints every one of them together.
  If you change a number here, re-run the lab and change it there too.
- The pixel counts (5,156 / 20,368 / 172,351 / 79,107 / 6,349) are
  rendered measurements, not arithmetic. They sit a couple of percent
  above the ideal `pi*r^2` for the circles because a boundary pixel is
  wholly in or wholly out with antialiasing off. The lesson and the lab
  both assert the RATIOS with a tolerance and never the raw counts as
  though they were exact; `expected-output/FIELDS.md` states exactly what
  is stable everywhere and what depends on the matplotlib version.
- The deuteranopia matrix is Machado, Oliveira and Fernandes (2009) at
  severity 1.0, applied in linear RGB. Say plainly, wherever it appears,
  that a simulation approximates a deficiency and does not reproduce
  anyone's experience.
- The roughly 8% prevalence figure for red-green colour vision deficiency
  in men is presented as a widely reported figure that varies by
  population, and is not attached to any of this day's five sources, none
  of which covers it. Keep that framing if you revise the sentence.
- Vega-Lite and plotly are not installed in the authoring environment and
  are described in the Tools section from public documentation only. No
  output is attributed to either anywhere. Commercial BI tools are named
  without any pricing claim, because none was run.
- scipy is not installed either, which is why Spearman's rank correlation
  is written out by hand in the lab rather than called from `scipy.stats`.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. No `github.com` or `localhost` URLs anywhere.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d127a-` or `d127f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX (`$$...$$`) anywhere in `index.mdx` — MDX parses `{`/`}` as JSX
  and it has broken the site build before (Day 109). Also avoid stray
  unescaped `{`/`}` and `<` outside code fences and inline code spans;
  every comparison in this lesson's prose is written inside backticks for
  that reason.
