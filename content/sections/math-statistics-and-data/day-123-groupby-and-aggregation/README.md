# Day 123 — Groupby and Aggregation

The second lesson of Week 18 ("pandas and Data Wrangling"), building
directly on Day 122's boolean masks and Day 120's index-alignment
fundamentals. Course 03's `data-analysis` subsection continues here with
`groupby`, pandas' implementation of the split-apply-combine pattern.

The through-line: **split, apply, combine — and the pieces must add back
up to the whole.** The lesson opens with the failure that makes this
concrete: `groupby` drops rows whose grouping key is missing, by default
and silently, so the sum of per-group totals comes back less than the true
overall total, with no exception raised anywhere. The gap always equals
exactly the missing-key rows' own total — the discipline the whole lesson
teaches is checking that reconciliation after every aggregation, which is
Day 122's partition invariant returning in a new costume.

From there the lesson covers `count()` versus `size()` (a second silent
trap), `.agg()`'s four forms with named aggregation as the readable modern
default, the shape distinction between `agg` (one row per group),
`transform` (the input's shape) and `apply` (the general, slowest escape
hatch), `GroupBy.filter` (whole groups, not rows), multi-key grouping and
its `MultiIndex`, `observed=` for categorical keys, an honestly measured
performance comparison, and a weighted mean checked two independent ways.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days — are
generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`groupby-flow.svg` is animated with CSS `@keyframes` inside the file, so
it animates wherever it is rendered as an image and prints as a still. It
carries a `@media (prefers-reduced-motion: reduce)` block that disables
every animation and restores the resting state, and the still frame
carries the whole meaning on its own. Both SVGs prefix every class, id and
keyframes name — `d123a-` in the architecture diagram, `d123f-` in the
flow diagram — because an inlined SVG's `<style>` block is not scoped to
that SVG and `url(#name)` resolves document-wide, so two diagrams on one
page would otherwise restyle each other.
