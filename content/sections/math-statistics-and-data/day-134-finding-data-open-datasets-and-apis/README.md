# Day 134 — Finding Data: Open Datasets and APIs

The first lesson of Week 20 ("Working with Real Data"), and the day that
sits between "I found something" and "I have a table." It follows Day
133, which closed Week 19 on turning exploration into a report, and it
precedes Day 135 (From API to DataFrame), which owns turning assembled
JSON rows into a tidy DataFrame — a step this day deliberately stops
short of.

The through-line: **the dataset you can get is never quite the dataset
you wanted, and the gap is where projects quietly die.** The lesson opens
with two public datasets that both have a column called
`unemployment_rate`, defined differently, whose join produces a chart
with a step change that is pure artifact — a definition change wearing
the costume of a labour-market shock. Nothing mechanical catches it: the
column names match, the dtypes match, the ranges overlap. Only the two
sources' data dictionaries, read as prose, reveal the mismatch. **Read
the dictionary before the data** is the day's one-sentence thesis.

Days 22-28 already covered HTTP, REST, authentication, status codes,
pagination and rate limits as mechanics — this lesson does not re-teach
any of that. It builds the judgement layer on top: how to assess a
source in five minutes, when to choose a bulk file over an API, and the
small set of client behaviours (pagination to exhaustion, bounded
backoff, conditional requests) that make using a live API polite and
reproducible rather than fragile and rude. Day 135 owns the JSON-to-
DataFrame transformation; Day 138 owns ethics, bias and provenance in
depth — this lesson raises licensing as a practical gate and leaves the
deeper ethics question to 138.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`pagination-flow.svg` is animated with CSS `@keyframes` inside the file,
so it animates wherever it is rendered as an image and prints as a still.
It carries a `@media (prefers-reduced-motion: reduce)` block that
disables every animation and restores the resting state, and the still
frame carries the whole meaning on its own. Both SVGs prefix every class,
id and keyframes name — `d134a-` in the architecture diagram, `d134f-` in
the flow diagram — because an inlined SVG's `<style>` block is not scoped
to that SVG and `url(#name)` resolves document-wide, so two diagrams on
one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every measured value quoted in this lesson (row counts, attempt counts,
  byte counts, checksums) is captured from a real run of this lesson's
  own lab on 2026-08-20, using Python 3.14.0, pandas 3.0.5 and pytest
  9.1.1 in this repository's authoring virtual environment. If you change
  a number here, re-run `bash tests/run_tests.sh` in the lab directory
  and change it in `expected-output/` too.
- **The two checksums quoted in "How it works" are real, not invented.**
  They were computed once with `hashlib.sha256(...).hexdigest()` against
  the exact fixture bytes shown beside them, and the lab's Exercise 5
  asserts the same values. Do not edit one without recomputing and
  updating the other.
- **`requests` was not installed in this lab's own venv and no output
  from it is reproduced.** The lesson describes it from its own public
  documentation only, and says so explicitly. It is installed separately
  in this repository's authoring tools environment for other purposes,
  which is a different thing from this lab's dependencies — do not
  conflate the two if you revise this section.
- **Hugging Face's `datasets` library is described from documentation
  only.** It is not installed anywhere in this repository's authoring
  environment, and no output from it is reproduced. Do not add a
  fabricated code output for it.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d134a-` or `d134f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX in `index.mdx` — MDX parses `{`/`}` as JSX and a `$$…$$` block
  has broken the site build before. Every brace in this lesson appears
  only inside a backtick-fenced inline code span or a fenced code block;
  keep any addition the same way.
- Do not re-teach HTTP mechanics (status codes, verbs, headers) already
  covered on Days 22-28; reference them by day number instead.
