# Day 133 — Building an EDA Report

The last lesson of Week 19 ("Data Visualization") and the week's
capstone. It sits after Day 132 (visual storytelling and chart honesty)
and before Day 134, which opens Week 20.

The through-line: **an EDA report is an argument with evidence, not a
gallery of charts.** The lesson opens with the failure every reader has
produced — a notebook with forty cells and thirty figures, all of them
correct, and a reader who reaches the end unable to say what was found.
The fix is not fewer charts; it is that every chart must answer a stated
question and the answer must be written down beside it.

Nothing on Days 127 to 132 fixes that failure, which is why this day
closes the week rather than adding another chart type. Correct charts are
the entry price; the argument is the product.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`figure-lifecycle-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. It carries a `@media (prefers-reduced-motion: reduce)` block that
disables every animation and restores the resting state, and the still
frame carries the whole meaning on its own. Both SVGs prefix every class,
id and keyframes name — `d133a-` in the architecture diagram, `d133f-`
in the flow diagram — because an inlined SVG's `<style>` block is not
scoped to that SVG and `url(#name)` resolves document-wide, so two
diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every output shown in this lesson is captured from a real run on the
  authoring machine on 2026-08-20, using matplotlib 3.11.1, seaborn
  0.13.2, pandas 3.0.5, NumPy 2.5.2 and pytest 9.1.1 in this repository's
  authoring virtual environment. If you change a number here, re-run the
  capture and change it in the lab's `expected-output/` directory too.
- **The lesson's quoted report output is verbatim, not retyped.** The
  conclusion block, the Figure 4 evidence paragraph and the omissions
  block all come from `expected-output/report-sample.md`. Re-render
  before editing any of them.
- **The claim-heuristic false negative is deliberate and must not be
  "fixed".** The lesson and the lab both state that `carries_claim`
  refuses "revenue tripled in all four regions", a real claim written
  with a word that is not on its list. That failure was found by writing
  the test and watching it fail, and it is the more instructive half of
  the honest account. Adding "tripled" to `CLAIM_WORDS` would remove the
  lesson's strongest point about what such a check can and cannot do.
- **The pandas Styler section reports an environment finding, not a
  recommendation.** `df.style` raises `AttributeError: The '.style'
  accessor requires jinja2` on the authoring machine, because jinja2 is
  not installed. The lesson therefore describes Styler from the pandas
  documentation and reproduces no Styler output. If jinja2 is added to
  the authoring environment later, re-run before changing that wording.
- Jupyter, nbconvert, Quarto and scipy are not installed on the authoring
  machine either. The Alternatives section says so explicitly for each,
  and no output is attributed to any of them.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d133a-` or `d133f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX in `index.mdx` — MDX parses `{`/`}` as JSX and a `$$…$$` block
  has broken the site build before. This lesson keeps every brace and
  every comparison operator inside a fenced code block for exactly that
  reason; keep any addition the same way.
- The flow diagram's three-gate split (4, 2, 1) is the general shape of
  the method. In this lesson's own twelve-candidate list all seven
  discarded figures fall at Gate 1, and both the diagram and the prose
  say so. Do not quietly reconcile the two by changing one of them.
