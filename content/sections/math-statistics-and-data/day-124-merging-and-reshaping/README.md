# Day 124 — Merging and Reshaping

The fifth lesson of Week 18 ("pandas and Data Wrangling"). Days 120-123 built
Series and DataFrames, loading and inspecting data, boolean-mask filtering,
and split-apply-combine with `groupby`. This day extends that same
reconciliation discipline to the operation most likely to silently change a
table's row count: the merge.

The through-line: **a join is a claim about cardinality, and pandas will not
check it for you unless you ask.** The lesson opens with two 100-row frames
merged on a fully duplicated key, producing exactly 10,000 rows with no error
and no warning — a per-key Cartesian product, exactly as `merge` is defined
to do. `validate=` is given as the fix immediately: state a cardinality
assumption (`"one_to_one"`, `"one_to_many"`) and pandas raises `MergeError`
the instant it is false, before the exploded frame is ever built.

From there the lesson covers `indicator=True` and the reconciliation check it
enables; the dtype-mismatch join, captured directly against pandas 3.0.5 and
carrying an honest correction to the classic "always silent" story (a plain
string key against `int64` now raises `ValueError`; a categorical key against
`int64` still fails silently); the four join types on one shared pair of
frames; `suffixes=`, `on=` versus `left_on=`/`right_on=`, and `.join()` on an
index; `concat`'s axis-0 and axis-1 alignment; the melt-to-pivot round trip;
and `pivot` versus `pivot_table` — an error versus a silently averaged
number.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay identical to `visuals.yml`. All
cross-links — to the lab and to neighbouring days — are generated by the
layout from central configuration; never hard-code repository or site URLs
inside content files.

`merge-flow.svg` is animated with CSS `@keyframes` inside the file, so it
animates wherever it is rendered as an image and prints as a still. It
carries a `@media (prefers-reduced-motion: reduce)` block that disables every
animation and restores the resting state, and the still frame carries the
whole meaning on its own. Both SVGs prefix every class, id and keyframes
name — `d124a-` in the architecture diagram, `d124f-` in the flow diagram —
because an inlined SVG's `<style>` block is not scoped to that SVG and
`url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every output shown in this lesson is captured from a real run on the
  authoring machine on 2026-08-19, using pandas 3.0.5, pyarrow 25.0.1 and
  NumPy 2.5.2 in the repository's authoring virtual environment. If you
  change a number here, re-run the capture and change it in the lab's
  `expected-output/` directory too.
- **The dtype-mismatch join finding is load-bearing and version-specific.**
  On pandas 3.0.5, merging an `int64` key against a plain `str` key raises
  `ValueError` rather than silently returning zero rows — this contradicts
  older material describing the join as always-silent, and the correction
  was verified directly against this pandas version, not assumed. The
  categorical-key case (`int64` versus a `pandas.Categorical` of the same
  digits) still fails silently and is the example this lesson uses for the
  classic behaviour. Do not soften or remove this distinction; re-verify
  before changing either claim if the pinned pandas version ever changes.
- `validate=` is the lesson's central claim ("the single best habit in this
  lesson") and must stay presented before every other technique, per the
  authoring brief this day was built from.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends markdown
  image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind its
  file's prefix (`d124a-` or `d124f-`), keep the `prefers-reduced-motion`

- No LaTeX in `index.mdx` — MDX parses `{`/`}` as JSX and a `$$…$$` block has
  broken the site build before. This lesson has no equations that require it.
- All data in every table this lesson quotes (`left_dup`, `right_dup`,

  small invented literal, stated as such. Keep any replacement equally
