# Day 140 — Section Project: An Exploratory Study

The last day of Week 20 ("Working with Real Data") and **the last day of
Course 03 — Math, Statistics, and Data, days 99 to 140.** Day 141 begins
Course 04, Machine Learning.

The through-line: **Course 03 taught a dozen separable skills; a study is
what happens when they have to hold each other up.** The failure mode of a
capstone is never a single skill. It is the seams — a clean dataset with an
unstated question, a beautiful chart of a leaked feature, a confident
conclusion from an exploration that examined forty things. Each component
correct, the study worthless.

The lesson opens with exactly that: a churn study whose data is clean, whose
chart is beautiful, whose interval is correctly computed, and which is
worthless in four separate ways, none of them a mistake inside a stage. It
closes with the honest statement that the worked study is exploratory, does
not establish causation, and names the design that would.

This day supplies the two things the Week 20 project brief cannot:

1. **A worked miniature study, executed end to end** on a 264-row synthetic
   dataset the lab ships, so the reader sees the whole arc performed rather
   than described.
2. **An acceptance harness** — `check_study(path)`, eight gates, findings
   that name the file, field, cleaning step or sentence at fault. That is the
   artefact the learner keeps, and it is what makes the section project
   gradeable by the learner before anyone else sees it.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay identical to `visuals.yml`. All
cross-links — to the lab and to neighbouring days — are generated by the
layout from central configuration; never hard-code repository or site URLs
inside content files.

`acceptance-flow.svg` is animated with CSS `@keyframes` inside the file, so
it animates wherever it is rendered as an image and prints as a still. It
carries a `@media (prefers-reduced-motion: reduce)` block that disables every
animation and restores the resting state. **The still frame carries the whole
meaning**: the seven passing gates are already green and marked PASS, the
failing one is already red and marked FAIL, and the verdict panel already
quotes the finding — the animation only shows the order the gates run in.
Both SVGs prefix every class, id and keyframes name — `d140a-` in the
architecture diagram, `d140f-` in the flow diagram — because an inlined SVG's
`<style>` block is not scoped to that SVG and `url(#name)` resolves
document-wide, so two diagrams on one page would otherwise restyle each
other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- **Every measured number in this lesson came from a real run** on the
  authoring machine on 2026-08-20 (macOS 26.5.2, Apple Silicon, Python
  3.14.0, NumPy 2.5.2, pandas 3.0.5, matplotlib 3.11.1, pytest 9.1.1) through
  a lab-local virtual environment. The load-bearing ones are: 264 rows in,
  245 out, 8 grain violations on arrival, four measured cleaning steps
  (8→2, 264→256, 6→0, 5→0), a 122/123 split, 4 logged comparisons, a measured
  difference of 5.50 ug/m3 with a 95% interval of 3.80 to 7.21 containing the
  planted true difference of 6.00, 11 files written, 8 gates, 54 reference
  tests, 33 solved starter tests, and `81 checks, 0 failure(s).` If you change
  any of them here, re-run the lab and change `expected-output/` too — never
  hand-edit a figure without re-running the code that produced it.
- **Nothing in this lab is sampled.** Unusually for this section there is no
  tolerance anywhere: every value is fixed by a seed or by arithmetic, so
  every assertion is an equality. Do not introduce a tolerance without
  introducing the sampling that would justify it.
- **The two PNG digests are machine-dependent** and are the only such values
  in the lab. Matplotlib rasterises text with whatever fonts it finds. Nothing
  asserts a PNG digest against a stored literal; what is asserted is that two
  builds on the same machine produce identical bytes. This is recorded in the
  lab's `expected-output/FIELDS.md` and must stay recorded.
- **Do not "fix" the worked study's grain assertion so that it passes on
  arrival.** It genuinely fails on arrival — eight byte-identical
  redeliveries — and `INGEST.json` records both that failure and the cleaning
  step that resolved it. An earlier draft wrote the record before cleaning and
  the harness correctly refused the study; the honest fix was to record both
  numbers, not to move the assertion.
- **Do not reword the report to please the uncertainty gate.** During
  authoring the gate flagged a sentence in the worked study's own report that
  did state an interval in words ("anywhere between 3.80 and 7.21"). The fix
  was to add the pattern to `acceptance.py`, with a comment recording why.
  That episode is quoted in the lesson and in the quiz; do not remove the
  comment.
- seaborn, scipy, statsmodels, scikit-learn and Jupyter/`nbconvert` are not
  used anywhere in this lab, and scipy, statsmodels and scikit-learn are not
  installed on the authoring machine. The Alternatives section says so
  explicitly for each, and no output is attributed to any of them. The
  confidence interval is built from `math.erf` alone, the Day 118
  construction.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the
  content. This lesson's five sources are fixed by the authoring brief — do
  not add or substitute one without updating the brief record. All five were
  confirmed to return HTTP 200 on 2026-08-20.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the
  exact H2 heading strings intact — the lesson validator checks them. Alt text
  must contain no square brackets: a closing bracket ends markdown image
  syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind its
  file's prefix (`d140a-` or `d140f-`), keep the `prefers-reduced-motion`
  block, keep the failing gate red in the resting state, and re-check with
  `xmllint --noout`.
- No LaTeX in `index.mdx` — MDX parses `{`/`}` as JSX and a `$$…$$` block has
  broken the site build before. Anything of the form `<=`, `</` or `<word`
  must be wrapped in backticks or a fenced block.
- The eight gate names are load-bearing: they appear in the lesson prose, both
  diagrams, the lab's `GATE_NAMES` tuple, the starter docstrings and the test
  assertions. Renaming one means changing all five places.
