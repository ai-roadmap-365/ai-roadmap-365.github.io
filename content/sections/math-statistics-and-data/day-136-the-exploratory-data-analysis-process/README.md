# Day 136 — The Exploratory Data Analysis Process

The first lesson of Week 20 ("Working with Real Data"), sitting after Day
135 (from API to DataFrame) and before Day 137 (thinking in features).

The through-line: **exploration and confirmation are different
activities, and the great sin is doing the first and reporting it as the
second.** Day 133 already covered the EDA *report* — the document, its
arc, captions carrying claims. This day owns the *process that happens
before the document exists*: the investigative loop, and specifically how
an honest analyst avoids fooling themselves while running it.

The lesson opens with the garden of forking paths, measured: an analyst
loads data with no real signal at all, tries a few groupings, subsets and
outcome variables, and — after examining forty combinations — one comes
back "significant at p < 0.05," with a plausible story attached, because
a plausible story can be attached to anything. The reader leaves with one
sentence: **a p-value is only meaningful if you can say how many things
you looked at.**

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`forking-paths-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. It carries a `@media (prefers-reduced-motion: reduce)` block that
disables every animation and restores the resting state, and the still
frame carries the whole meaning on its own: all eight candidate boxes,
the wires between them, and every label are drawn and legible with
animation off. Both SVGs prefix every class, id and keyframes name —
`d136a-` in the architecture diagram, `d136f-` in the flow diagram —
because an inlined SVG's `<style>` block is not scoped to that SVG and
`url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every measured number in this lesson is captured from a real run on the
  authoring machine on 2026-08-20, using Python 3.14.0, NumPy 2.5.2,
  pandas 3.0.5 and pytest 9.1.1 in this repository's lab-local virtual
  environment. If you change a number here, re-run the lab's numbered
  scripts and change it in `expected-output/` too — do not hand-edit a
  figure without re-running the code that produced it.
- **The seed choices are deliberate and documented, not arbitrary.**
  `HOLDOUT_SEED=1` was picked after sweeping seeds 1-199 and finding 157
  produce the same qualitative outcome; `NARRATIVE_SEED=6` with
  `NARRATIVE_N_ROWS=80` was picked specifically because it reliably clears
  the "publishable effect size" threshold in exercise 2. Both are recorded
  with their reasoning in `metadata.yml` and `expected-output/FIELDS.md`
  in the lab directory. Do not change a seed without re-verifying the
  downstream numbers this lesson quotes.
- **The narrative dataset's second subset cut must stay independent of
  every outcome column.** An earlier version built it from the median of
  the outcome column being tested, which created real data leakage
  (effect sizes above d=1.0 on data with zero true effect). This is
  recorded as an honesty note in the lab's `metadata.yml`; do not
  reintroduce that pattern when editing `dataset.py`.
- statsmodels, Jupyter/`nbconvert` and Weights & Biases are not installed
  on the authoring machine. The Alternatives section says so explicitly
  for each, and no output is attributed to any of them.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. This lesson's five sources are fixed by the authoring
  brief — do not add or substitute one without updating the brief record.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d136a-` or `d136f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX in `index.mdx` — MDX parses `{`/`}` as JSX and a `$$…$$` block
  has broken the site build before. Comparison operators like `p < 0.05`
  are safe as plain prose only because a space follows the `<`; anything
  of the form `<=`, `</`, or `<word` must be wrapped in backticks or a
  fenced block instead.
- The flow diagram's eight-leaf split (two subset choices, times two
  outcome choices, times two cutoff choices) is the general shape of the
  method. Do not quietly change the count without updating both the
  diagram's caption and the prose describing it.
