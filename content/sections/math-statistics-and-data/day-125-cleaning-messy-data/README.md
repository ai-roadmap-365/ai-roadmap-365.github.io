# Day 125 — Cleaning Messy Data

The third lesson of Week 18 ("pandas and Data Wrangling"), building
directly on Days 120–124's pandas foundation. Course 03's `data-analysis`
subsection continues here with the discipline of turning a genuinely
messy DataFrame into one whose values reflect deliberate decisions rather
than accidents of how the data happened to arrive. Day 126 turns today's
techniques into a reproducible pipeline; today is the techniques
themselves, and what each one actually costs — the week's project,
"Messy Dataset Rescue," depends on both.

The through-line: **cleaning is a sequence of irreversible decisions
about data you do not have, and every one of them changes the answer.**
The lesson opens with the failure that looks like good practice:
mean-impute a numeric column's missing values, then check the mean. It is
exactly unchanged — which is why checking it proves nothing. What
actually moves is the standard deviation (it strictly shrinks) and a real
correlation with another column (it strictly *attenuates*, toward zero —
the opposite of the original assumption this lesson was drafted against,
and the lesson says so explicitly, with the algebraic reason why).

From there the lesson covers why data is missing (MCAR/MAR/MNAR, and why
MNAR is the common, unrepairable case), detection (`isna()` by column and
row, missingness patterns), removal (`dropna`'s `how`/`thresh`/`subset`),
filling (`fillna`, and `ffill`'s real bug on unsorted data), the
missing-indicator habit, silent type coercion
(`to_numeric(errors='coerce')`), string normalisation, the two different
meanings of "duplicate," outliers as a judgement call rather than a
procedure, and a hand-rolled cleaning contract proven able to raise.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days — are
generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`imputation-flow.svg` is animated with CSS `@keyframes` inside the file,
so it animates wherever it is rendered as an image and prints as a still.
It carries a `@media (prefers-reduced-motion: reduce)` block that
disables every animation and restores the resting state, and the still
frame carries the whole meaning on its own. Both SVGs prefix every class,
id and keyframes name — `d125a-` in the architecture diagram, `d125f-`
in the flow diagram — because an inlined SVG's `<style>` block is not
scoped to that SVG and `url(#name)` resolves document-wide, so two
diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every output shown in this lesson is captured from a real run on the
  authoring machine on 2026-08-19, using pandas 3.0.5, pyarrow 25.0.1 and
  NumPy 2.5.2 in the lab's own `.venv`. The captures live in the lab's
  `expected-output/` directory; if you change a number here, re-run the
  lab and change it there too.
- **Exercise 1's correlation direction is load-bearing and deliberately
  contrarian.** This lesson was originally drafted expecting mean
  imputation to *inflate* a correlation with an untouched column. Direct
  measurement showed the opposite — correlation strictly attenuates — and
  is provable algebraically from the Pearson correlation formula. If you
  revise this lesson, do not "correct" the direction back toward the
  original assumption without re-running the measurement yourself.
- matplotlib, scipy and scikit-learn are not installed in the authoring
  environment. scikit-learn's `SimpleImputer`, pyjanitor, Great
  Expectations and pandera are described from their public documentation
  in the Tools section as design contrasts; say so plainly and do not
  attribute any output to them.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. No `github.com` or `localhost` URLs anywhere.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d125a-` or `d125f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX (`$$...$$`) anywhere in `index.mdx` — MDX parses `{`/`}` as JSX
  and it has broken the site build before (Day 109). Also avoid stray
  unescaped `{`/`}` outside code fences and inline code spans.
