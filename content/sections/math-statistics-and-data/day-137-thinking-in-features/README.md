# Day 137 — Thinking in Features

The fourth lesson of Week 20 ("Working with Real Data"), the last week of
Course 03. It sits after Day 136 (the exploratory data analysis process)
and before Day 138, and it is the last chance to establish feature
discipline before Course 04 begins modelling on Day 141.

The through-line: **a feature encodes a hypothesis about what matters —
and the most dangerous features are the ones that quietly encode the
answer.** The lesson opens by measuring a leak rather than warning about
one: the same model, split and seed score 1.0000 with a column derived
from the outcome and 0.6400 without it. The lesson that follows is not
"leakage is bad" but the more useful **"a result that looks too good is
a bug report"**.

Because the reader has not met a machine-learning library yet, every
model in the day is written from scratch in NumPy — a logistic
regression trained by Day 111's gradient descent and a nearest-centroid
classifier built on Day 107's distance. scikit-learn is not installed on
the authoring machine, which turns a constraint into an advantage.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days —
are generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`cyclical-encoding-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. It carries a `@media (prefers-reduced-motion: reduce)` block that
disables every animation and restores the resting state, and the still
frame carries the whole meaning on its own. Both SVGs prefix every class,
id and keyframes name — `d137a-` in the architecture diagram, `d137f-`
in the flow diagram — because an inlined SVG's `<style>` block is not
scoped to that SVG and `url(#name)` resolves document-wide, so two
diagrams on one page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every number in this lesson is captured from a real run on the
  authoring machine on 2026-08-20, using pandas 3.0.5, NumPy 2.5.2 and
  pytest 9.1.1 on Python 3.14.0 in a lab-local virtual environment. If
  you change a number here, re-run the lab's harness and change it in
  `expected-output/` too. The full capture is in the lab's
  `expected-output/test-run.txt`.
- **The negative scaler result is the day's most important finding and
  must not be "fixed".** Fitting a `Standardiser` on all the data before
  the split was measured over 200 random splits at **-0.06 accuracy
  points** — the contaminated version scored slightly *lower*. The
  explanation is arithmetic: standardisation applies one affine map to
  both halves, so contaminating it can only change relative feature
  weighting, and a logistic regression run to convergence is nearly
  invariant to that. Equal-width binning and a rank transform were tried
  as alternatives and behaved the same way or worse. The lesson
  therefore demonstrates real contamination with a **group-mean
  imputer** (8.22 points), and keeps the scaler result as the finding it
  is. Do not replace it with a construction that produces the expected
  sign.
- **scikit-learn is not installed on the authoring machine.** The
  Alternatives section describes `Pipeline` and `ColumnTransformer` from
  the library's documentation and says plainly that no output is
  reproduced. The lab's harness asserts scikit-learn's absence. If it is
  ever installed here, re-run before changing that wording.
- **No pricing is quoted for the commercial feature-store product**,
  because none was verified. Do not add a figure from memory or from a
  secondary source.
- The 81.67-point temporal gap comes from a deliberately sharp
  construction, and both the lesson and the lab's `FIELDS.md` say so.
  The durable part of that finding is that the time-ordered score falls
  *below* the majority-class baseline — the model is confidently wrong,
  not merely uninformed. Keep that comparison whenever you touch the
  numbers.
- The vocabulary gap (2.45 points) is small and configuration-sensitive;
  eight combinations were measured and two of them favoured the honest
  vocabulary. `FIELDS.md` records this. Do not restate the gap as a
  general law.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d137a-` or `d137f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX in `index.mdx` — MDX parses braces as JSX and a display-maths
  block has broken the site build before. This lesson keeps every brace
  and every comparison operator inside a fenced code block or backticks
  for exactly that reason; keep any addition the same way.
