# Day 112 — Visualizing Optimization

The sixth and last lesson of Week 16 ("Linear Algebra II and Calculus"),
following directly from Day 111's gradient-descent loop and leading into the
week's project, the Gradient Descent Visualizer.

The organising claim, returned to in every section:

> **A final loss number cannot tell two optimization runs apart. Two runs
> measured for this lesson land within 3% of the same final loss and differ
> by over 13x in path length. Only a picture shows why.**

## The audience decision this lesson is built around

The reader has just finished writing a gradient-descent loop from scratch
(Day 111) with no image-processing background at all. So:

1. **The opening is a measurement, not a definition.** Two real runs, their
   final losses and their path lengths, printed exactly as the lab produced
   them, before any picture-drawing technique is introduced.
2. **matplotlib's absence is treated as pedagogy, not an apology.** The
   authoring environment genuinely has no matplotlib, scipy, pandas or
   Plotly installed. Rather than working around that, the lesson leans into
   it: every picture is built from NumPy arrays and Pillow's `ImageDraw`
   alone, so nothing about how a contour plot reaches the screen is hidden.
3. **Every claim is measured, not merely illustrated.** The log-axis
   collinearity claim is proved by fitting a line to the picture's own drawn
   pixel coordinates and reporting the residual, not by asserting "this
   looks like a straight line."

## The numbers this lesson is built on

**2.431009e-03 vs 2.507203e-03, and 5.6075 vs 75.9767.** The two-run
comparison that opens the lesson: a well-conditioned bowl (`a = b = 1`) and
an ill-conditioned one (`a = 1, b = 25`), same start, same learning rate,
same step count. A 3.04% gap in final loss; a 13.55x gap in path length.

**1.7e-13.** The maximum residual when a straight line is fit to the
well-conditioned run's log-scale loss curve, in the same pixel coordinates
the picture is drawn in. This is not asserted in prose — it is measured from
the drawn geometry, because `a = b = 1` makes the update an exact linear
recursion.

**eta = 1.0, eta = 2.05, eta = 2.15.** The three learning-rate landmarks in
the sweep on `f(x) = x^2`: the exact theoretical divergence threshold, the
largest swept rate whose blow-up has not yet overflowed float64 in 300
steps, and the smallest swept rate whose blow-up has.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay identical to `visuals.yml`. All
cross-links — to the lab and to neighbouring days — are generated by the
layout from central configuration; never hard-code repository or site URLs
inside content files.

`descent-path-flow.svg` is animated with CSS `@keyframes` inside the file,
so it animates wherever it is rendered as an image and prints as a still. It
carries a `@media (prefers-reduced-motion: reduce)` block that disables
every animation and restores the resting state, and the still frame carries
the whole meaning on its own. Both SVGs prefix every class, id and
keyframes name — `d112a-` in the architecture diagram, `d112f-` in the flow
diagram — because an inlined SVG's `<style>` block is not scoped to that SVG
and `url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

**No LaTeX anywhere in `index.mdx`.** MDX parses `{` and `}` as JSX, and a
`$$…$$` block broke the site build on Day 109. Every formula in this lesson
is written in a fenced ```text block or inline backticks instead.
