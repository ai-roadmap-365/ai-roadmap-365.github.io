# Day 120 — pandas: Series and DataFrames

The first lesson of Week 18 ("pandas and Data Wrangling"), and the reader's
first contact with pandas — Course 03 leaves the `mathematics-for-ai`
subsection behind and opens the new `data-analysis` subsection with this day.
It leans directly on Day 104 (NumPy arrays and vectorised thinking, the
direct ancestor: a Series is an ndarray with an index bolted on) and Day 116
(descriptive statistics, which `.describe()` reproduces exactly).

The through-line: **a DataFrame is not a spreadsheet. It is a set of Series
sharing one index, and the index is the thing that makes pandas different —
and surprising.** The lesson opens with the failure that teaches it: adding
two Series whose indexes do not match aligns on label rather than position,
producing `NaN` wherever a label appears on only one side, with no exception
raised anywhere.

The lesson is built on **pandas 3.0**, and is explicit that two of its
defaults changed things almost every earlier tutorial still gets wrong:
Copy-on-Write is now unconditional (chained assignment silently leaves the
original object unchanged, though pandas 3.0.5 does raise a
`ChainedAssignmentError` warning naming the fix), and the default dtype for a
column of strings is `str`, not `object`. Every captured output in this
lesson states the pandas version beside it and says plainly when behaviour on
2.x would differ.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay identical to `visuals.yml`. All
cross-links — to the lab and to neighbouring days — are generated by the
layout from central configuration; never hard-code repository or site URLs
inside content files.

`index-alignment-flow.svg` is animated with CSS `@keyframes` inside the file,
so it animates wherever it is rendered as an image and prints as a still. It
carries a `@media (prefers-reduced-motion: reduce)` block that disables every
animation and restores the resting state, and the still frame carries the
whole meaning on its own. Both SVGs prefix every class, id and keyframes
name — `d120a-` in the architecture diagram, `d120f-` in the flow diagram —
because an inlined SVG's `<style>` block is not scoped to that SVG and
`url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every output shown in this lesson is captured from a real run on the
  authoring machine on 2026-08-19, using pandas 3.0.5, pyarrow 25.0.1 and
  NumPy 2.5.2 in the lab's own `.venv`. The captures live in the lab's
  `expected-output/` directory; if you change a number here, re-run the lab
  and change it there too.
- **The pandas version is version-specific evidence, not incidental
  detail.** `pd.Series(['a','b']).dtype` is `str` on 3.0.5 and `object` on
  2.x; chained assignment's behaviour under Copy-on-Write differs between
  3.0 (unconditional) and 2.x (optional). State the version beside every
  captured value that depends on it, per `expected-output/FIELDS.md` in the
  lab.
- Do not describe pandas 3.0.5's chained-assignment behaviour as silent with
  no warning — it is not. It raises a real `ChainedAssignmentError` warning
  (a `Warning` subclass, not a raised exception) naming the exact fix. The
  ORIGINAL FRAME is still left unchanged either way; only the warning claim
  must stay accurate to what was actually observed.
- matplotlib, scipy and polars are not installed in the authoring
  environment. polars is described from its public documentation as a
  deliberate design contrast (no implicit row index); say so plainly and do
  not attribute any output to it.
- Report timing comparisons (vectorised versus `.apply`) as a ratio and a
  shape, never a millisecond figure — the specific number is one machine on
  one day.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. No `github.com` or `localhost` URLs anywhere.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
