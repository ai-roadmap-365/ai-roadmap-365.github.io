# Day 119 — Analyzing an Experiment End to End

The seventh and final lesson of Week 17 ("Probability and Statistics") and
the week's capstone. Day 118 built hypothesis tests, confidence intervals,
permutation tests, power and the cost of peeking; today does not re-derive
any of that machinery. It walks the *process* of analyzing one complete
experiment end to end, on two shipped datasets, and teaches the ways a
correct calculation still reaches a wrong conclusion.

The organising sentence, returned to throughout:

> **Statistical validity is a property of the process that produced a
> number, not of the number itself.**

## The opening failure

An experiment that looks entirely respectable: a healthy sample size, a
clean 1.8 percentage point lift, p = 0.03, a confidence interval excluding
zero. Every rule Day 118 taught says ship it. Then one more fact: the
analyst looked at seven metrics and this is the one that came back, or the
realized split is 52/48 against a planned 50/50. The result evaporates —
not because the arithmetic was wrong, but because the process that produced
the number was.

## What the lesson covers, each with a measured number

- The eight-step analysis process, in order: the question and its decision,
  a pre-registered primary metric, a written analysis plan, the
  sample-ratio mismatch (SRM) check, looking at the data before testing it,
  the test and the interval together, careful segment analysis, and the
  plain-language verdict.
- **Two shipped, seeded datasets, analyzed with the identical nine-function
  pipeline.** `exp_a.csv` (16,000 rows): SRM check passes (p=1.0), primary
  metric moves 10.13% → 11.91% (1.79pp lift, z=3.61, p=0.0003, 95% CI
  [0.82, 2.76]pp), guardrail holds (latency −0.51ms), all segments agree in
  sign, verdict **ship**.
- `exp_b.csv` (20,000 rows): SRM check fails (observed split 48%/52%,
  chi-squared p=1.5×10⁻⁸ against α=0.001), and every one of three segments
  shows a **negative** effect (−3.56, −2.48, −4.30 percentage points) while
  the pooled number shows a **positive** one (+3.89pp) — a measured
  Simpson's paradox. Verdict: **do not trust this result**, and the verdict
  function explicitly refuses to compute an effect estimate at all.
- **Peeking, demonstrated on real data.** Dataset A's running p-value,
  checked every 500 rows in arrival order, dips below 0.05 at row 4,000,
  climbs back above it by row 5,000, and only settles for good after row
  5,500 — even though the full-sample verdict at row 16,000 is also
  significant, showing why a stopping rule declared in advance matters even
  when the final answer turns out to be correct.
- Novelty effects, statistical versus practical significance as a decision
  problem, and "inconclusive" as a legitimate, first-class outcome.
- An AI-practice thread: shipping a model version is the identical
  discipline — a pre-registered offline metric, a guardrail that can veto a
  winning model, a held-out set sized by a power calculation, and a
  reported interval instead of a single leaderboard number.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text stays identical to `visuals.yml`.
All cross-links — to the lab and to neighbouring days — are generated by
the layout from central configuration; never hard-code repository or site
URLs inside content files.

`srm-and-simpson-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. It carries a `@media (prefers-reduced-motion: reduce)` block that
disables every animation and restores the resting state, and the still
frame carries the whole meaning on its own — both panels' labels, numbers
and arrow directions are present without motion. Both SVGs prefix every
class, id and keyframes name — `d119a-` in the architecture diagram,
`d119f-` in the flow diagram — because an inlined SVG's `<style>` block is
not scoped to that SVG and `url(#name)` resolves document-wide, so two
diagrams on one page would otherwise restyle each other.

No LaTeX appears anywhere in `index.mdx`. Every formula is written in
inline backticks or plain prose, because MDX parses `{` and `}` as JSX and
a `$$…$$` block broke the site build on Day 109.
