# Day 138 — Data Ethics, Bias, and Provenance

The fifth lesson of Week 20 ("Working with Real Data"), and the ethics day.
It follows Day 137 (Thinking in Features) and precedes Day 139. It builds
directly on Day 134 (source assessment, licences, provenance records),
Day 117 (sampling and the central limit theorem), Day 116 (Simpson's
paradox), Day 130 (what each view of a distribution hides) and Day 132
(chart honesty).

The through-line: **data is not found, it is made — by someone, for a
purpose, under constraints — and every one of those decisions is still in
the file.**

Ethics days fail in a specific way: they become a list of principles nobody
can act on, or a sermon. This one is neither. **Everything in it is either
measurable or procedural** — something the reader can compute, check, or
write down. The lesson opens with the measurable failure and leads with the
strongest available argument, which is arithmetic rather than opinion: a
sampling frame that reaches one group at a tenth of its population share
produces a model whose bias for that group is 5.9459 at n = 500 and 5.9397
at n = 50,000, while the interval around it tightens 11.5-fold. That is
Day 117's bias-versus-error distinction with consequences.

Where a question is genuinely a value judgement rather than a calculation —
which fairness criterion a system should satisfy — the lesson says so
explicitly, presents the disagreement accurately, and asks the reader to
declare their choice rather than pretending arithmetic settles it. That
editorial stance is deliberate and should not be softened in either
direction on revision.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source list
from `sources.yml`, and uses `lesson.yml` for navigation, metadata and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay identical to `visuals.yml`. All
cross-links — to the lab and to neighbouring days — are generated by the
layout from central configuration; never hard-code repository or site URLs
inside content files.

`frame-vs-population-flow.svg` is animated with CSS `@keyframes` inside the
file, so it animates wherever it is rendered as an image and prints as a
still. It carries a `@media (prefers-reduced-motion: reduce)` block that
disables every animation and restores the resting state, and the still
frame carries the whole meaning on its own — every measured value appears
as static text. Both SVGs prefix every class, id and keyframes name —
`d138a-` in the architecture diagram, `d138f-` in the flow diagram —
because an inlined SVG's `<style>` block is not scoped to that SVG and
`url(#name)` resolves document-wide, so two diagrams on one page would
otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- **Every measured value quoted in this lesson is captured from a real run
  of this lesson's own lab on 2026-08-20**, using Python 3.14.0, NumPy
  2.5.2, pandas 3.0.5 and pytest 9.1.1 in a lab-local virtual environment.
  If you change a number here, re-run `bash tests/run_tests.sh` in the lab
  directory and change it in `expected-output/` too. The values pinned to
  the NumPy random stream and `seed=138` are listed in the lab's
  `expected-output/FIELDS.md`, as are the ones that involve no randomness
  at all.
- **No fairness toolkit was installed or run.** Fairlearn and AIF360 are
  described from their published documentation only, and no output from
  either is reproduced anywhere in this lesson or lab. The Fairlearn
  description was checked against its user guide on 2026-08-20, on which
  date the documentation site served version 0.15.0.dev0. Do not add a
  fabricated code output for either.
- **Differential privacy is described, not demonstrated.** No differentially
  private mechanism was implemented or run here, and the lesson says so.
  Keep that disclaimer if you expand the section.
- **Every dataset in the lab is synthetic**, constructed from a seeded
  generator, and the lesson, the lab README, `00_brief.md` and `security.md`
  all state that this is a deliberate design decision rather than a
  limitation. Do not replace any fixture with a real dataset about real
  people.
- **The fairness section must assert the incompatibility, not a preferred
  criterion.** Presenting one of demographic parity, equal opportunity or
  equal precision as the correct answer would misrepresent a live and
  good-faith disagreement. Keep all three metrics reported for all three
  policies, and keep the paragraph saying the choice is a value judgement
  that must be declared.
- Historical facts in this lesson are dated and attributed: Yule 1903 and
  Simpson 1951, Sweeney's k-anonymity in 2002, differential privacy in 2006,
  the fairness impossibility results in 2016 and 2017, Datasheets for
  Datasets first posted 23 March 2018 and revised through December 2021,
  model cards in 2019, the Belmont Report in 1979, and the GDPR applicable
  from 25 May 2018. If you revise any of them, verify rather than
  approximate.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends markdown
  image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind its
  file's prefix (`d138a-` or `d138f-`), keep the `prefers-reduced-motion`
