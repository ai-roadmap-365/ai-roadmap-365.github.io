# Day 126 — A Reproducible Cleaning Pipeline

The last day of Week 18 ("pandas and Data Wrangling") and the week's
capstone lesson. Course 03's `data-analysis` subsection closes this week
with the engineering discipline around Day 125's cleaning techniques:
mean imputation, `to_numeric(errors="coerce")`, string normalisation, and
the cleaning-contract idea, all covered on Day 125 and used here, not
re-taught.

The through-line: **a notebook that produced the right answer once is not
a pipeline.** The lesson opens with a clip step that recomputes its
threshold from whatever data is currently passing through it — correct
the first time it runs, silently different the second time it runs on its
own output, exactly what a retried scheduled job does by accident. From
there the lesson builds every property a reproducible pipeline needs:
idempotence (`pipeline(pipeline(df))` equals `pipeline(df)`), determinism
with an explicit sort tie-break, a step log that reconciles, input and
output contracts proven able to fail (not just to pass), `.pipe()`
chaining versus sequential composition and the real inspectability
tradeoff between them, declared order-dependence between two steps that
do not commute, a Parquet checkpoint that preserves a nullable `Int64`
column's missing value exactly, and a manifest tying an output back to
its input hash, config hash, step log and output hash.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel
with it: the site layout renders the body at the day route, injects the
quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source
list from `sources.yml`, and uses `lesson.yml` for navigation, metadata
and time estimates. Images are referenced from `index.mdx` with relative
paths into `assets/`, and their alt text must stay identical to
`visuals.yml`. All cross-links — to the lab and to neighbouring days — are
generated by the layout from central configuration; never hard-code
repository or site URLs inside content files.

`pipeline-flow.svg` is animated with CSS `@keyframes` inside the file, so
it animates wherever it is rendered as an image and prints as a still. It
carries a `@media (prefers-reduced-motion: reduce)` block that disables
every animation and restores the resting state, and the still frame
carries the whole meaning on its own. Both SVGs prefix every class, id and
keyframes name — `d126a-` in the architecture diagram, `d126f-` in the
flow diagram — because an inlined SVG's `<style>` block is not scoped to
that SVG and `url(#name)` resolves document-wide, so two diagrams on one
page would otherwise restyle each other.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler — if a fact or figure is not verified, leave it out rather than
  approximating it.
- Every output shown in this lesson is captured from a real run on the
  authoring machine on 2026-08-19, using pandas 3.0.5, pyarrow 25.0.1 and
  NumPy 2.5.2 in the lab's own `.venv`. The captures live in the lab's
  `expected-output/` directory; if you change a number here, re-run the
  lab and change it there too.
- The literal SHA-256 hex digests shown in this lesson are real, captured
  values, not guarantees for every machine — `expected-output/FIELDS.md`
  in the lab states exactly what is stable everywhere (row counts, deltas,
  hash equality/inequality properties) and what is captured-but-may-differ
  (the specific digest string, dependent on pandas' CSV float formatting).
- matplotlib, scipy, scikit-learn, polars, pandera and Great Expectations
  are not installed in the authoring environment. pandera, Great
  Expectations and a workflow runner (Prefect/Dagster) are described in
  the Tools section from public documentation only; say so plainly and do
  not attribute any output to them.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in
  the content. No `github.com` or `localhost` URLs anywhere.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep
  the exact H2 heading strings intact — the lesson validator checks them.
  Alt text must contain no square brackets: a closing bracket ends
  markdown image syntax and the alt renders broken.
- If you edit either SVG, keep every class, id and keyframes name behind
  its file's prefix (`d126a-` or `d126f-`), keep the
  `prefers-reduced-motion` block, and re-check with `xmllint --noout`.
- No LaTeX (`$$...$$`) anywhere in `index.mdx` — MDX parses `{`/`}` as JSX
  and it has broken the site build before (Day 109). Also avoid stray
  unescaped `{`/`}` outside code fences and inline code spans.
