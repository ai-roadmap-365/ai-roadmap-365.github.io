# Day 023 — REST Fundamentals: Resources and Verbs

The fourth week's first architecture lesson. It builds the resource-and-verb
model of REST — nouns at addresses, standard HTTP verbs, statelessness,
representations, safety and idempotency, and a high-level comparison of REST
with RPC and GraphQL — and connects it to reading and designing the web and
model APIs a practitioner works with daily.

## What this directory contains

| File | Purpose |
| --- | --- |
| `index.mdx` | The full lesson body (pure markdown after the frontmatter), with all sixteen standard sections |
| `lesson.yml` | Lesson metadata: id, slug, learning promise, objectives, prerequisites, timings, tags |
| `quiz.yml` | 8 multiple-choice questions with answers and explanations |
| `glossary.yml` | 12 plain-language definitions of the lesson's key terms |
| `sources.yml` | The verified external sources this lesson draws on |
| `visuals.yml` | Registry of the lesson's diagrams with titles, alt text, and descriptions |
| `assets/rest-resources.svg` | Architecture diagram: the collection /users and item /users/1 with the four verbs |
| `assets/crud-http-map.svg` | Flow diagram: the CRUD operations mapped to HTTP methods and status codes |

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with
it: the site layout renders the body at the day route, injects the quiz from
`quiz.yml`, the glossary from `glossary.yml`, and the source list from
`sources.yml`, and uses `lesson.yml` for navigation, metadata, and time
estimates. Images are referenced from `index.mdx` with relative paths into
`assets/`, and their alt text must stay in sync with `visuals.yml`. All
cross-links (to the lab, to neighboring days) are generated by the layout from
central configuration — never hard-code repository or site URLs inside content
files.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no
  filler of any kind — if a fact or figure is not verified, leave it out
  rather than approximating it.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the
  content.
- When you revise any file in this directory, update `last_verified` in
  `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the
  exact H2 heading strings intact — the lesson validator checks them.
- Regenerate any downstream exports (search index, print/PDF builds) after
  edits so rendered outputs match the source.
