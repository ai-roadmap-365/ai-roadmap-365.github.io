# Day 042 — Section Review: Your Computing Foundations Toolkit

The final lesson of the computing-foundations section (days 1-42). It consolidates the six areas of Course 1 — the machine, the command line, the internet, APIs, git/GitHub, and systems foundations — into one connected mental model, traces a single action through every layer, guides an honest self-assessment, and bridges to Course 2 (Programming with Python).

## What this directory contains

| File | Purpose |
| --- | --- |
| `index.mdx` | The full review lesson body (pure markdown after the frontmatter), with all sixteen standard sections |
| `lesson.yml` | Lesson metadata: id, slug, learning promise, consolidation objectives, prerequisites, timings, tags |
| `quiz.yml` | 8 multiple-choice questions drawing across the whole section, with answers and explanations |
| `glossary.yml` | 12 plain-language definitions revisiting the section's key terms |
| `sources.yml` | The verified external sources this review points learners to for filling gaps |
| `visuals.yml` | Registry of the review's two diagrams with titles, alt text, and descriptions |
| `assets/foundations-map.svg` | Architecture diagram: the six domains of Course 1 as one connected system |
| `assets/stack-journey.svg` | Flow diagram: one action — call an API and store the result — traced through every layer |

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with it: the site layout renders the body at the day route, injects the quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source list from `sources.yml`, and uses `lesson.yml` for navigation, metadata, and time estimates. Images are referenced from `index.mdx` with relative paths into `assets/`, and their alt text must stay in sync with `visuals.yml`. All cross-links (to the lab, to neighboring days, to Course 2) are generated by the layout from central configuration — never hard-code repository or site URLs inside content files.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no filler of any kind — if a fact or figure is not verified, leave it out rather than approximating it.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the content.
- When you revise any file in this directory, update `last_verified` in `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the exact H2 heading strings intact — the lesson validator checks them.
- As the section-closing review, keep the recap accurate to the days it summarizes; if an earlier day's slug or emphasis changes, update the cross-references here.
