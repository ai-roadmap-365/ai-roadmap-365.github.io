# Day 002 — The CPU: Fetch, Decode, Execute

The second lesson of the computing-foundations section. It opens the CPU: registers, the ALU, the control unit, the program counter, and the instruction register; the fetch-decode-execute cycle in slow motion; clocks and gigahertz; the x86 and ARM instruction sets and why Apple Silicon mattered; pipelining and why modern CPUs do more per tick; and the AI connection — why CPUs are flexible while GPUs win at bulk math, and what "CPU-bound" means.

## How this lesson is rendered

`index.mdx` provides the lesson body, and the sidecar YAML files travel with it: the site layout renders the body at the day route, injects the quiz from `quiz.yml`, the glossary from `glossary.yml`, and the source list from `sources.yml`, and uses `lesson.yml` for navigation, metadata, and time estimates. Images are referenced from `index.mdx` with relative paths into `assets/`, and their alt text must stay in sync with `visuals.yml`. All cross-links (to the lab, to neighboring days) are generated by the layout from central configuration — never hard-code repository or site URLs inside content files.

## Editing rules

- Every file must ship complete: no stub text, no unfinished sections, no filler of any kind — if a fact or figure is not verified, leave it out rather than approximating it.
- Cite only sources listed in `sources.yml`; do not add URLs elsewhere in the content.
- When you revise any file in this directory, update `last_verified` in `lesson.yml` to the revision date.
- Keep image alt text in `index.mdx` and `visuals.yml` identical, and keep the exact H2 heading strings intact — the lesson validator checks them.
- The trace output quoted in the lesson's hands-on section is a real captured run of the lab's simulator; if the simulator's output format ever changes, re-capture and update both the lab's `expected-output/` files and the lesson's code blocks together.
